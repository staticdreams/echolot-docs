每篇教程都完整地讲解一项任务。它们都使用 **Alpenglow**，一个虚构的户外装备商店：位于 `https://demo.echolot.dev` 的[演示 API](/docs/tutorials/demo-api)，以及一个已包含各类请求的示例工作区。你需要一台运行 macOS 15 或更高版本、搭载 Apple 芯片的 Mac，并安装 Echolot。发送到演示服务的任何内容都不会被存储。

## Alpenglow 工作区 [#the-alpenglow-workspace]

大多数教程要么自己新建工作区，要么从 Alpenglow 开始。获取方式：

1. 下载 [Alpenglow.echolot.zip](/examples/Alpenglow.echolot.zip)。
2. 在访达中双击 zip 文件解压，得到 `Alpenglow.echolot`。
3. 双击 `Alpenglow.echolot`，Echolot 会在工作区窗口中打开它。你也可以选取**文件 › 打开工作区…**（<kbd>⌘</kbd><kbd>O</kbd>）并选择它。

Alpenglow 在选择**无环境**时即可使用：它的工作区变量指向演示 API。其中包含：

| 文件夹 | 内容 |
| --- | --- |
| Auth | **Sign in**，它把访问令牌存入机密变量 `{{token}}`；**Who am I**；**Orders with OAuth 2** |
| Catalog | **List products**、**Search**、**Get product**、**Categories**、GraphQL 请求 **Search products**、**Export the catalog**（14 MB） |
| Orders | **List orders**、**Create order**、**Get order**、**Cancel order**，都通过文件夹的 Bearer 认证发送令牌 |
| Realtime | **Order updates**（WebSocket）、**Order events**（Server-Sent Events）、**Support chat**（Socket.IO）、**Warehouse sensors**（MQTT） |
| Inventory | 三个 gRPC 调用：**List warehouses**、**Watch stock**、**Reserve stock** |
| Agent tools | 两个 MCP 请求，**search_catalog** 和 **order_status**，发往服务器 **Alpenglow MCP** |
| Echo | 发往 `/echo` 端点的请求：你发送的内容、状态、重定向、Basic 认证、Cookie、XML 和 HTML |

它还有三个环境（**Local**、**Staging** 和受保护的 **Production**；Staging 和 Production 是虚构的地址）、三个流程（**Place a test order**、**Morning stock check**、**Order status on webhook**）、MCP 服务器 **Alpenglow MCP**，以及规范 `alpenglow.yaml`、`shop.graphql` 和 `inventory.proto`。

## 在 Mac 上运行 gRPC、Socket.IO 和 MQTT 服务器 [#servers-on-your-mac-for-grpc-socketio-and-mqtt]

演示 API 无法提供 gRPC、Socket.IO 或 MQTT。文档仓库的 `examples/servers` 中有适用于它们的小型服务器。它们需要 [Bun](https://bun.sh)，并且只在你的 Mac 上监听：

```sh
git clone https://github.com/staticdreams/echolot-docs.git
cd echolot-docs/examples/servers
bun install
bun run realtime   # Socket.IO on http://localhost:3001 (namespace /support), MQTT on mqtt://localhost:1883
bun run grpc       # the Inventory service on localhost:50051 (in a second Terminal window)
```

Alpenglow 的 **Support chat**、**Warehouse sensors** 和 **Inventory** 请求已经指向这些地址。要停止服务器，按 <kbd>Control</kbd>-<kbd>C</kbd>。

<Callout title="演示 API 有限制">
  它对同一地址每分钟接受 120 个请求，导出、WebSocket 和 Server-Sent Events 为每分钟 10 个。超出限制时，它会返回 `429 Too Many Requests`；等待一分钟后再次发送即可。
</Callout>
