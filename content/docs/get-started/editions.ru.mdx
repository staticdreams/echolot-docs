Echolot выходит в двух версиях, собранных из одного кода: **версия с сайта** [echolot.dev](https://echolot.dev) и
версия из **Mac App Store**. Версия из App Store работает в песочнице Apple (App Sandbox). Песочница позволяет
приложению пользоваться сетью, читать и записывать выбранные вами файлы и хранить собственные данные. Запускать
другие программы на вашем Mac и читать или записывать файлы других приложений она не позволяет. Почти все различия
ниже следуют из этого.

Версии для App Store пока нет в App Store. Всё, что написано на этой странице, описывает то, как она устроена.

## Что есть в каждой версии [#what-each-edition-has]

| | Версия с сайта | Mac App Store |
| --- | --- | --- |
| Все протоколы: HTTP/1.1, HTTP/2, HTTP/3, GraphQL, gRPC, WebSocket, SSE, Socket.IO, MQTT | ✓ | ✓ |
| Рабочие пространства в виде файлов, Git, окружения, секреты в Связке ключей | ✓ | ✓ |
| Скрипты, тесты, прогон, прогоны на данных | ✓ | ✓ |
| История, сохранённые ответы, шифрование на диске | ✓ | ✓ |
| Спецификации, моки, сценарии с расписаниями и вебхуками | ✓ | ✓ |
| Импорт и экспорт | ✓ | ✓ |
| Быстрая отправка, её глобальное сочетание клавиш, действия Быстрых команд, Быстрый просмотр | ✓ | ✓ |
| MCP-серверы по HTTP | ✓ | ✓ |
| MCP-серверы, которые работают как локальная программа (stdio: `npx`, `uvx` …) | ✓ | Хранятся в рабочем пространстве, но не запускаются. Используйте инструмент командной строки или версию с сайта. |
| Ассистент с API-ключами, Ollama и другими совместимыми серверами, встроенная модель Apple | ✓ | ✓ |
| Ассистент с агентами командной строки (Claude Code, Codex, Gemini CLI) | ✓ | ✗ |
| Echo и его комментарии от ИИ | ✓ | ✓ |
| MCP-сервер Echolot для внешних агентов | ✓ | ✓, через отдельно установленный инструмент командной строки |
| Импорт MCP-серверов из конфигураций других приложений | Находятся автоматически | Вы выбираете файл конфигурации; панель открывается в нужной папке |
| Подключение Claude Code, Cursor, VS Code, Codex | ✓ | ✓, через отдельно установленный инструмент командной строки |
| Расширение для Claude Desktop (`.mcpb`), **Добавить в Claude** | ✓ | ✗ |
| Инструмент командной строки | Внутри приложения; **Echolot › Установить инструмент командной строки…** | Устанавливается отдельно (zip-архив со страницы релизов) |
| Обновления | В приложении, **Echolot › Проверить обновления…** | App Store |
| Срок действия бета-сборок | Истекает через 30 дней после выхода | Не истекает (беты идут через TestFlight) |

Файлы за пределами рабочего пространства тоже обрабатываются по-разному. В версии из App Store Echolot может прочитать
файл только после того, как вы выбрали его в панели открытия. Он запоминает каждое открытое вами рабочее пространство
и каждый файл, который вы выбрали для запроса (тело, передаваемое из файла, часть формы, клиентский сертификат), в том
числе после перезапуска и после перемещения файла. Отправка, которой нужен файл, не выданный Echolot (например, путь,
вписанный в файл запроса вручную), завершается ошибкой `Echolot is not allowed to read “…”`; выберите **Разрешить доступ…** в ответе с ошибкой и укажите файл. См. [Устранение неполадок](/docs/troubleshooting).

## Какую выбрать [#which-to-choose]

Выберите **версию с сайта**, если вы:

- используете MCP-серверы, которые работают как локальные программы (большинство серверов, запускаемых через `npx`,
  `uvx`, `docker` или исполняемый файл),
- хотите, чтобы Ассистент управлял Claude Code, Codex или Gemini CLI,
- хотите, чтобы инструмент командной строки устанавливался и обновлялся вместе с приложением, или нужно расширение
  для Claude Desktop в один клик.

Выберите **версию из App Store**, если вы предпочитаете приложения из App Store с его обновлениями и песочницей вокруг
приложения, а ваши MCP-серверы доступны по HTTP.

Обе версии открывают одни и те же рабочие пространства, так что передумать можно в любой момент.

## Переход между версиями [#moving-between-editions]

Для macOS обе версии — одно и то же приложение, поэтому устанавливайте только одну: завершите и удалите ту, от которой
уходите ([Удаление](/docs/get-started/install#uninstall)), затем установите другую.

- **Рабочие пространства** — обычные папки, и они открываются в обеих версиях. В версии из App Store откройте каждое из
  них один раз через **Файл › Открыть рабочее пространство…** или из Finder, чтобы песочница позволила Echolot его
  читать; после этого оно остаётся в **Файл › Открыть недавние**.
- **Секреты** остаются в вашей связке ключей для входа и общие для обеих версий. Когда другая версия впервые читает
  секрет, который создала не она, macOS один раз спрашивает про каждый элемент; выберите **Всегда разрешать**.
  Инструмент командной строки спрашивает так же.
- **Ключи моделей** для Ассистента во второй версии тоже запрашиваются один раз, или добавьте их заново в
  **Настройки › Ассистент**.
- **История и сохранённые ответы** остаются у той версии, которая их записала: у каждой версии своя папка хранения.
  Запросы не теряются, пропадают только прошлые ответы.

## Где каждая версия хранит данные [#where-each-edition-keeps-its-data]

Рабочие пространства лежат там, где вы их сохранили, в обеих версиях. Собственные данные Echolot (тела сохранённых
ответов, история, отчёты о сбоях, разговоры с Ассистентом и рабочее пространство «Примеры») лежат здесь:

| Версия | Папка |
| --- | --- |
| Версия с сайта | `~/Library/Application Support/Echolot` |
| Mac App Store | `~/Library/Containers/com.staticdreams.Echolot/Data/Library/Application Support/Echolot` |

**Настройки › О программе › Ответы и история › Показать в Finder** открывает нужную папку. Если её удалить, пропадут
история и сохранённые ответы, но не запросы.

## Инструмент командной строки для пользователей App Store [#the-command-line-tool-for-app-store-users]

В версии из App Store нет инструмента командной строки, потому что App Store не разрешает устанавливать код за
пределами приложения. Установите инструмент отдельно: скачайте `echolot-<version>-macos.zip` со
[страницы релизов](https://github.com/staticdreams/echolot-public/releases). Срок действия инструмента не истекает. См.
[Инструмент командной строки](/docs/cli).

Он нужен, чтобы:

- запускать рабочие пространства в Терминале и CI,
- запускать MCP-серверы, которые стартуют как локальные программы (`echolot mcp check`, `echolot mcp serve`),
- подключать внешних агентов, например Claude Code, Cursor, VS Code и Codex. В их конфигурациях указан этот
  инструмент; пока рабочее пространство открыто в приложении, их вызовы выполняются в приложении, где вы их одобряете.
  См. [Агенты](/docs/ai/agents).
