Плагин Echolot учит Claude Code работать с Echolot. [MCP-сервер](/docs/ai/agents) Echolot даёт агенту инструменты, а
плагин объясняет Claude, когда и как ими пользоваться: какой инструмент подходит какому протоколу, где в проекте лежит
рабочее пространство, как не допустить учётные данные в разговор. С ним запрос, который Claude делает, пока вы пишете
код, сохраняется в вашем рабочем пространстве, проверяется, остаётся в истории, и вы можете открыть его в приложении,
а не пропадает вместе с командой `curl`, когда сеанс заканчивается.

## Что добавляет плагин [#what-the-plugin-adds]

Плагин — это один навык с именем `echolot` и его справочные файлы. Claude загружает его, когда задача касается API
вашего проекта.

| Часть | Что она даёт Claude |
| --- | --- |
| Навык | Когда использовать Echolot, как настроить проект, цикл для каждого запроса (окружение, создание, отправка, проверка, отчёт) и что делать, когда одобрение отклонено |
| Справка по настройке | Установка Echolot, подключение MCP-сервера, политики, наборы инструментов и секреты |
| Справка по файлам запросов | TOML рабочего пространства для каждого вида запросов: HTTP, GraphQL, WebSocket, Socket.IO, MQTT, gRPC и MCP |
| Рецепты | Наборы смоук-тестов, документы OpenAPI, постраничная навигация, проверки в реальном времени, моки, сценарии, тестирование MCP-сервера, CI |
| Скрипт | Создаёт пустое рабочее пространство с окружениями `local` и `production` |

В плагине нет ни кода, который выполняется сам, ни сервера: Claude по-прежнему обращается к Echolot через MCP-сервер и
[инструмент командной строки](/docs/cli), с одобрениями и ограничениями, описанными в разделе
[Внешние агенты](/docs/ai/agents).

## Перед установкой [#before-you-install]

Вам понадобятся:

- **Claude Code** с плагинами.
- **Инструмент командной строки Echolot** в вашем `PATH`, чтобы работала команда `echolot --version`. См.
  [Инструмент командной строки](/docs/cli).

<Edition only="appstore">
  В версии из App Store внутри приложения нет инструмента командной строки. Установите инструмент командной строки
  отдельно (**Загрузить инструмент командной строки** в **Настройки › Агенты** ведёт к загрузкам); плагин работает с
  ним точно так же.
</Edition>

## Установите плагин [#install-the-plugin]

<Steps>
<Step>
В Claude Code добавьте маркетплейс Echolot:

```text
/plugin marketplace add staticdreams/echolot-claude-plugin
```
</Step>
<Step>
Установите из него плагин:

```text
/plugin install echolot@echolot
```
</Step>
<Step>
Попросите Claude настроить ваш проект, как описано ниже. Плагин устанавливается один раз; каждый проект настраивается
один раз.
</Step>
</Steps>

Чтобы получить новую версию, выполните `/plugin marketplace update echolot`. Чтобы удалить плагин, выполните
`/plugin uninstall echolot@echolot`.

## Настройте проект [#set-up-a-project]

В папке проекта попросите Claude:

```text
Настрой Echolot для этого проекта
```

После этого Claude делает следующее, и ничего больше:

1. Проверяет, что `echolot` запускается.
2. Ищет в проекте рабочее пространство — папку, имя которой оканчивается на `.echolot`. Если его нет, создаёт его в
   корне проекта с окружениями `local` и `production` и добавляет хосты, которые использует ваш проект, как переменные.
3. Задаёт вам один вопрос: хотите ли вы одобрять его изменения в приложении Echolot или позволить ему работать без
   присмотра. См. [Одобрения или работа без присмотра](#approvals-or-unattended).
4. Регистрирует MCP-сервер Echolot для проекта. При этом в корне проекта создаётся `.mcp.json`:

   ```sh
   claude mcp add --scope project echolot -- echolot mcp serve ./alpenglow.echolot --toolsets all --env local
   ```

5. Предлагает добавить в `CLAUDE.md` вашего проекта короткую заметку о том, что вызовы ваших API идут через Echolot.

Затем он останавливается и говорит, что делать дальше:

1. Если вы выбрали одобрения в приложении, откройте рабочее пространство в Echolot, включите
   **Разрешить агентам работать с открытыми рабочими пространствами** в **Настройки › Агенты** и включите нужные
   наборы инструментов в разделе **Инструменты для агентов**. Приложение предлагает **Запросы** и **Сценарии**, пока
   вы не включите остальные.
2. Перезапустите Claude Code или выполните `/mcp` и одобрите сервер проекта.

Закоммитьте рабочее пространство и `.mcp.json`. Ни в том, ни в другом нет секретов, а ваши коллеги получат ту же
настройку из репозитория.

## Одобрения или работа без присмотра [#approvals-or-unattended]

MCP-сервер решает, как он работает, при запуске.

| Как он работает | Что происходит |
| --- | --- |
| Рабочее пространство открыто в Echolot, и агенты включены | Вызовы Claude выполняются в приложении. Изменение или отправка, которая может изменить данные, спрашивает вас на листе. Вы видите, как каждый запрос появляется в боковой панели. |
| Сам по себе, с `--policy permissive` | Отправки и изменения выполняются без вопросов. Удаление отклоняется, как и отправки в защищённые окружения и на новые хосты. |
| Сам по себе, без указанной политики | Чтение и безопасные отправки выполняются. Всё остальное отклоняется. |

Одобрения в приложении подходят для времени разработки: вы видите, что делает Claude, и можете ему отказать. Работа
без присмотра подходит для долгой задачи, за которой вы не хотите следить. Чтобы перейти от одного к другому, откройте
или закройте рабочее пространство в Echolot и выполните `/mcp`, чтобы переподключиться. О политиках см.
[Сам по себе](/docs/ai/agents#on-its-own).

## О чём просить [#what-to-ask-for]

Упоминать Echolot не нужно. Когда у проекта есть рабочее пространство, Claude использует его для вызовов API этого
проекта.

| Вы просите | Что Claude делает в Echolot |
| --- | --- |
| «Войди как демо-пользователь и покажи мои заказы» | Сохраняет пароль как секрет, сохраняет запрос входа, который захватывает токен из своего ответа, и отправляет запрос списка с этим токеном. Токен никогда не попадает в разговор. |
| «Сделай набор смоук-тестов для API заказов» | Папка с запросами на список, получение, создание, обновление и по одному случаю с ошибкой для каждого, с проверками, связанными через значения, которые они захватывают. Затем он запускает папку и сообщает, что не прошло. |
| «Странице нужен API списка желаний, которого ещё нет» | Мок-сервер, из вашего документа OpenAPI или с маршрутами, созданными вручную, и тестовыми данными, и запросы для его маршрутов. |
| «Почему этот эндпоинт через какое-то время начинает падать?» | Отправляет запрос снова и снова, сравнивает обмены в истории и говорит, в чём причина: в API или в тесте. |
| «Проверь, что события заказов приходят по WebSocket» | Открывает сеанс, оформляет заказ другим запросом и читает то, что получил сеанс. |
| «Протестируй инструменты нашего MCP-сервера» | Добавляет сервер, проверяет его и сохраняет вызов каждого инструмента с проверками его результата. |
| «Войди, создай заказ и опрашивай, пока его не доставят» | Рисует сценарий с этими блоками. Он запускается, когда вы его одобрите. |
| «Запускай тесты API в CI» | Команда `echolot run` для вашего пайплайна, с отчётом и именами секретов, которые ей нужны. |

Каждая строка оставляет что-то в рабочем пространстве: запросы, проверки, мок или сценарий, которые можно открыть,
изменить и запустить снова в Echolot.

## Чего Claude не делает [#what-claude-does-not-do]

Навык держит Claude в рамках этих правил:

- **Никаких учётных данных в файле или в разговоре.** Пароль или ключ, который вы ему даёте, сразу попадает в
  секретную переменную, и дальше появляется только `{{её имя}}`. Токены из ответа на вход захватывает Echolot, и через
  Claude они никогда не проходят.
- **Никакого удаления**, если вы не просили удалить именно этот объект.
- **Никаких тестов в защищённом или продакшен-окружении**, если вы не просили. Отправки в защищённое окружение всегда
  спрашивают вас.
- **Никаких скриптов по собственной инициативе.** Скрипты — это код, которому вы должны доверять: Claude предлагает
  скрипт и говорит, куда он пойдёт, а Echolot спрашивает вас, прежде чем его выполнить.
- **Не больше, чем вы просили.** «Настрой» — это только настройка. «Протестируй этот эндпоинт» — это запросы и
  проверки для этого эндпоинта, а не набор тестов.
- **Никакой молчаливой смены инструмента.** Когда одобрение отклонено или инструмента нет, Claude говорит, что нужно,
  и ждёт. К `curl` он не возвращается.

## Если что-то не работает [#troubleshooting]

- **Claude по-прежнему использует `curl`.** Проверьте, что плагин установлен (`/plugin`), что у проекта есть рабочее
  пространство и что `/mcp` показывает сервер `echolot` подключённым. Если так, добавьте заметку в ваш `CLAUDE.md`:
  попросите Claude «добавь заметку об Echolot в CLAUDE.md».
- **Изменения отклоняются, и ничто вас не спрашивает.** Сервер работает сам по себе. Откройте рабочее пространство в
  Echolot, включите **Разрешить агентам работать с открытыми рабочими пространствами** и выполните `/mcp`, чтобы
  переподключиться. Или попросите Claude переключить сервер на политику permissive.
- **Claude говорит, что инструмента нет.** Его набор выключен. Включите его в **Настройки › Агенты**, в разделе
  **Инструменты для агентов**, и переподключитесь.
- **Запрос, который написал Claude, не появляется.** Сервер, работающий сам по себе, читает рабочее пространство при
  запуске. Выполните `/mcp` и переподключите `echolot`. Через приложение новые запросы появляются сразу.
