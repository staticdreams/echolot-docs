Echolot은 두 종류의 데이터를 분리해서 보관합니다. 작업 공간은 원하는 곳에 두는 폴더입니다. Echolot 자체의 데이터(응답 본문, 기록, 충돌 보고서)는 사용자의
Mac의 저장 폴더에 있습니다. 그 폴더를 삭제하면 기록은 잃어도 요청은 절대 잃지 않습니다.

## 데이터가 있는 곳 [#where-things-are]

| 항목 | 위치 |
| --- | --- |
| 작업 공간 | 만들거나 보관한 어느 곳이든. |
| 비밀 값, OAuth 토큰, 암호화 키 | 로그인 키체인. |
| 응답 본문과 통신 캡처 | Echolot 저장 폴더의 `Payloads`. |
| 기록 | Echolot 저장 폴더의 `History`. 작업 공간마다 파일 하나. |
| 공유하지 않은 어시스턴트 대화 | Echolot 저장 폴더의 `Assistant`. |
| 충돌 보고서(허용한 경우) | Echolot 저장 폴더의 `Crash Reports`. |
| 직접 만든 코드 템플릿 | Echolot 저장 폴더의 `Code Templates`. [내보내기](/docs/workspaces/exporting#copy-a-request-as-code)를 참조하세요. |
| 예제 작업 공간 | Echolot 저장 폴더의 `Examples.echolot`. |
| 설정, 전역 변수, 작업 공간별 활성 환경 | Echolot의 환경설정. |

Echolot의 저장 폴더는 `~/Library/Application Support/Echolot`입니다. 열려면 <strong>설정 › 정보</strong>로 이동해 <strong>응답 및 기록</strong> 옆의 <strong>Finder에서 보기</strong>를
클릭하세요.

<Edition only="appstore">
  App Store 에디션은 같은 데이터를 `~/Library/Application Support/Echolot` 대신 자체 컨테이너에 보관합니다. <strong>설정 › 정보 › Finder에서 보기</strong>는 두
  에디션 모두에서 올바른 폴더를 엽니다. 작업 공간은 두 에디션 모두 사용자가 보관한 곳에 그대로 있으며 양쪽에서 열립니다.
</Edition>

## 응답 본문 [#response-bodies]

모든 응답 본문은 도착하는 즉시 메모리가 아니라 파일로 바로 기록되므로 수 기가바이트짜리 응답도 문제없습니다. 본문은 몇 번을 받든 한 번만 저장됩니다.
같은 요청을 같은 응답으로 열 번 보내도 사본은 하나만 보관됩니다.

본문이 차지할 수 있는 공간은 <strong>설정 › 저장 공간 › 응답 본문</strong>에서 정합니다. <strong>응답 본문 최대 보관 크기</strong>는 1, 2, 5(기본값), 10, 20, 50 GB입니다. 이
크기를 넘으면 Echolot이 가장 오래전에 사용한 본문부터 제거합니다. 다음은 항상 유지됩니다.

- 열려 있는 탭에 표시된 본문,
- 저장된 요청마다 최신 응답. 다시 시작한 뒤에도 표시되도록 합니다.
- `$responseJSONPath` 같은 [동적 값](/docs/requests/dynamic-values)을 통해 다른 요청이 읽는 본문.

한도 아래의 줄에는 저장된 본문이 디스크에서 차지하는 크기가 표시됩니다. 그 공간을 지금 확보하려면 <strong>저장된 본문 제거…</strong>를 클릭하고 확인하세요. Echolot은
열려 있는 윈도우에 필요한 것만 유지합니다. 열려 있는 탭에 표시된 본문과 열려 있는 작업 공간의 요청별 최신 응답입니다. 열려 있지 않은 작업 공간의 본문을
포함해 나머지 본문은 모두 삭제되며 되돌릴 수 없습니다. 요청과 기록은 그대로 남고, 오래된 응답은 본문 없이 표시됩니다.

기록은 각 교환이 보낸 요청을 보관합니다. 256 KB보다 큰 요청 본문은 기록에 보관되지 않으며, 통신 캡처에는 시작 부분이 남아 있습니다.

## 기록 [#history]

<strong>설정 › 저장 공간 › 기록</strong>은 [기록](/docs/workspaces/history)이 요청마다 보관하는 응답 개수를 10, 25, 50(기본값), 100, 200 중에서 정합니다.
오래된 항목부터 삭제됩니다. 모든 전송은 보낸 주체(사용자, 실행, 에이전트)와 함께 보관됩니다. 작업 공간의 기록을 지우려면 [기록 페이지](/docs/workspaces/history)의
⋯ 메뉴에서 <strong>기록 지우기…</strong>를 사용하세요. 요청 자체의 기록은 그 기록 목록의 같은 메뉴에서 지웁니다.

## 디스크의 응답 본문 암호화 [#encrypt-response-bodies-on-disk]

응답에는 개인 데이터, 토큰, API가 돌려주는 그 밖의 모든 것이 들어 있을 수 있습니다. 암호화를 켜면 키체인의 키 없이는 Echolot의 저장 폴더에 있는 응답의
어떤 부분도 읽을 수 없습니다.

1. <strong>설정 › 저장 공간</strong>을 엽니다.
2. <strong>디스크에 저장된 응답 본문 암호화</strong>를 켭니다.

Echolot은 처음에 키를 만들어 로그인 키체인에 <strong>Echolot response storage key</strong>라는 이름으로 보관합니다. 새 본문은 바로 암호화되어 기록됩니다. 이미
저장된 본문은 백그라운드에서 암호화되며, 설정에 진행 상황(“860개 중 120개 암호화 중…”)이 표시되고 이어서 “저장된 본문 860개가 모두 암호화되어 있습니다.” 같은
상태가 표시됩니다.

본문은 카운터 모드의 AES-256으로 암호화되므로, Echolot은 나머지를 복호화하지 않고도 본문의 어느 부분이든 읽을 수 있습니다. 뷰어, 응답 안의 검색,
큰 본문도 이전과 똑같이 작동합니다.

### 암호화 대상 [#what-it-covers]

| 암호화됨 | 암호화되지 않음 |
| --- | --- |
| 응답 본문 | 작업 공간 파일(어차피 비밀 값이 들어 있지 않음) |
| 통신 캡처(송수신한 원본 바이트) | 기록 파일: 이름, 주소, 헤더, 상태, 소요 시간 |
| 본문의 서식이 적용된 사본 | Echolot의 환경설정 |

기록 파일은 암호화되지 않으므로 암호화가 켜져 있는 동안에는 본문 텍스트를 보관하지 않습니다. 그러면 검색은 본문 내용이 아니라 요청의 이름, 주소, 헤더로
요청을 찾습니다. 암호화를 켜면 기록이 이미 색인한 본문 텍스트가 제거됩니다. 비밀 값은 암호화가 켜져 있든 꺼져 있든 기록에서 가려집니다.

### 끄기 [#turning-it-off]

<strong>디스크에 저장된 응답 본문 암호화</strong>를 끕니다. 새 본문은 다시 암호화되지 않은 채 기록되고, Echolot은 저장된 본문을 백그라운드에서 복호화합니다(“860개 중
120개 복호화 중…”). 키는 키체인에 남아 있으므로 아직 복호화되지 않은 본문도 계속 읽을 수 있습니다.

암호화가 켜져 있는 동안 기록된 응답은 기록의 본문 검색에서 제외된 채로 남습니다. 그 이후의 응답은 다시 본문으로 검색할 수 있습니다.

<Callout type="warn">
  키체인의 <strong>Echolot response storage key</strong> 항목을 보관하세요. Echolot은 암호화된 본문을 읽으려면 이 키가 필요합니다.
</Callout>

키를 만들거나 읽을 수 없으면 설정에 그 사실(“암호화 키를 키체인에 보관할 수 없어…”)이 표시되고 본문은 그대로 유지됩니다.

## 공간 확보 [#free-up-room]

- <strong>설정 › 저장 공간</strong>에서 <strong>응답 본문 최대 보관 크기</strong>를 낮춥니다. Echolot이 잠시 뒤에 가장 오래전에 사용한 본문을 제거합니다.
- [기록](/docs/workspaces/history#clear-history) 페이지에서 요청 하나 또는 작업 공간 전체의 기록을 지웁니다.
- Echolot을 종료하고 저장 폴더의 `Payloads` 또는 `History`를 삭제합니다. 이전 응답과 기록은 잃지만 요청, 환경, 모든 작업 공간 파일은 그대로 남습니다.
