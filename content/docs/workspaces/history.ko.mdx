Echolot은 작업 공간에서 이루어진 모든 교환을 보관합니다. 보낸 요청과 받은 응답, 그리고 보낸 주체입니다. 사용자, 실행, 플로, 에이전트가 보낸 것이 모두
같은 곳에 쌓입니다. 이전 응답으로 돌아가거나, 어떤 값을 돌려준 요청을 찾거나, 에이전트가 무엇을 했는지 확인하려면 기록을 사용하세요.

## 기록 페이지 열기 [#open-the-history-page]

- **보기 › 기록**(<kbd>⌘</kbd><kbd>Y</kbd>).
- 페이지 헤더의 **기록**. 다시 클릭하면 이전에 보던 페이지로 돌아갑니다.

페이지에는 교환이 날짜별로, 최신순으로 나열됩니다. 각 행에는 상태(응답을 받지 못한 전송은 **실패**), 메서드, 요청의 이름, 주소, 보낸 주체, 시각이
표시됩니다. **저장 안 됨**은 저장된 적이 없는 요청의 교환을, **삭제됨**은 이후에 요청이 삭제된 교환을 나타냅니다.

## 기록되는 것 [#what-is-recorded]

- 요청 페이지, [실행](/docs/requests/runner), 플로, [빠른 보내기](/docs/mac/quick-send), [단축어](/docs/mac/shortcuts),
  [어시스턴트](/docs/ai/assistant), [외부 에이전트](/docs/ai/agents)에서 보낸 모든 종류의 요청 전송.
- 응답 없이 실패한 전송과 그 오류.
- WebSocket, Socket.IO, MQTT 세션. 닫힌 뒤에 기록되며 연결과 모든 메시지의 로그가 담깁니다.

GraphQL 스키마나 명세를 가져오는 것처럼 Echolot이 자체 용도로 보내는 전송은 기록되지 않습니다. 명령줄 도구는 기록을 남기지 않습니다.

교환을 보낸 주체는 행에 표시됩니다.

| 표시 | 보낸 주체 |
| --- | --- |
| **나** | 앱에서 직접 보낸 사용자. |
| **실행** | 실행에서의 한 번의 실행. |
| **플로:** 이름 | 플로. |
| **에이전트** | 내장 어시스턴트. |
| 클라이언트의 이름 | Claude Code 같은, Echolot의 MCP 서버를 통한 외부 에이전트. |

## 검색과 필터 [#search-and-filter]

**이름, URL, 헤더 및 본문 검색**에 입력하세요. 두 글자는 이름과 주소를 검색하고, 세 글자 이상은 본문까지 검색합니다. 일치 항목은 단어의 시작뿐 아니라
텍스트의 어느 위치에서든 찾습니다.

**보낸 주체**로 목록을 좁힙니다. **모두**, **나**, **실행**(실행과 플로), **에이전트**(어시스턴트와 외부 에이전트)입니다. 그 옆의 개수는 교환 또는 일치
항목이 몇 개인지 알려 줍니다.

검색이 다루는 범위는 다음과 같습니다.

- 각 텍스트 본문의 처음 256 KB. JSON, XML, HTML, 텍스트, 폼 데이터, 이벤트 스트림 등입니다. 이미지, 압축 파일 등 바이너리 본문은 검색하지 않습니다.
- [암호화](/docs/workspaces/storage-and-encryption)가 켜져 있는 동안에는 본문 텍스트가 전혀 포함되지 않습니다. 이때 검색은 이름, 주소, 헤더만 찾습니다.
- 비밀 값은 절대 포함되지 않습니다. 기록이 나열하고 검색하는 내용에서 가려져 있으므로 검색으로 비밀 값을 추측할 수 없습니다.

## 교환 살펴보기 [#look-at-an-exchange]

행을 클릭하면 선택됩니다. <kbd>↑</kbd>와 <kbd>↓</kbd>로 목록을 이동합니다.

- <kbd>Space</kbd>는 훑어보기를 표시합니다. 상태, 보낸 시각, 걸린 시간, 크기와 유형, 보낸 주체, 환경, 요청이 표시되며, 보기, 주소 복사, 비교
  버튼이 있습니다.
- <kbd>↩</kbd> 또는 더블 클릭하면 엽니다. 저장된 요청의 교환은 그 요청에서 해당 응답으로 열립니다. 저장된 요청이 없는 교환은 응답 헤더와 본문이 있는
  시트에서 열립니다.

행을 Control 키를 누른 채 클릭하면 다음 명령이 나옵니다.

| 명령 | 하는 일 |
| --- | --- |
| **요청에서 보기** | 이 응답이 선택된 상태로 요청을 엽니다. |
| **교환 보기** | 교환을 시트에서 엽니다. |
| **이전 응답과 비교** | 요청의 그 이전 응답과 비교합니다. |
| **OpenAPI 명세에 추가…** | 응답을 명세에 문서화합니다. [트래픽으로 만드는 명세](/docs/specs/specs-from-traffic)를 참조하세요. |
| **모의 서버 예제로 저장…** | 요청이 따르는 명세에 이름이 있는 예제로 응답을 저장합니다. [모의 서버](/docs/mocks)를 참조하세요. |
| **URL 복사** | 주소를 복사합니다. |
| **삭제** | 이 교환을 기록에서 제거합니다. |

## 요청의 자체 기록 [#a-requests-own-history]

요청 페이지에서 응답 패널의 띠에 있는 시계 버튼은 요청의 응답이 몇 개인지 보여 줍니다. 클릭하면 목록이 열리며 상태, 시각, 보낸 주체, 소요 시간, 크기가
나옵니다.

- 응답을 클릭하면 응답 패널에 표시됩니다. 그 위의 막대에 **이전 응답**, 시각, 보낸 주체가 표시되고 **최신 응답과 비교**와 **최신 항목 보기**가
  나옵니다.
- 행 위에 포인터를 두고 화살표를 클릭하면 표시 중인 응답과 비교합니다.
- <strong>⋯ › 이 요청의 기록 지우기…</strong>는 먼저 묻고 그 요청의 이전 응답을 제거합니다. 요청 자체는 그대로 남습니다.

## 두 응답 비교 [#compare-two-responses]

요청의 기록 목록에서, **최신 응답과 비교**로, 또는 기록 페이지의 **이전 응답과 비교**로 비교합니다. 시트 위쪽에는 두 응답이 나란히 표시되며 오래된
쪽은 −, 새로운 쪽은 +로 표시됩니다. 그 아래에는 두 응답 사이에서 바뀐 줄이 각 변경 위아래 세 줄과 함께 나옵니다.

- **본문**은 본문을 비교합니다. 차이가 없으면 “본문이 바이트 단위까지 동일합니다.”, 레이아웃만 다르면 “본문은 서식만 다릅니다.”라고 표시합니다.
- **상태 및 헤더**는 상태 줄과 헤더를 비교합니다.

아래쪽의 개수는 추가되고 제거된 줄이 몇 개인지 알려 줍니다. 변경된 줄은 최대 20,000개까지 표시됩니다.

## 기록이 보관되는 기간 [#how-long-history-is-kept]

기록은 요청마다 최신 응답을 보관합니다. 몇 개를 보관할지는 **설정 › 저장 공간 › 요청당 기록**에서 10, 25, 50(기본값), 100, 200 중에서 선택합니다.
오래된 항목부터 삭제됩니다. 각 요청의 최신 응답은 본문을 유지하므로 다시 시작한 뒤에도 표시됩니다.

본문은 별도로 저장되며 자체 크기 한도(**응답 본문 최대 보관 크기**, 기본값 5 GB)가 있습니다. 한도를 넘으면 가장 오래 사용하지 않은 본문부터 제거되므로
오래된 항목에는 “이 본문은 더 이상 저장되어 있지 않습니다.”라고 표시될 수 있습니다. [저장 공간과 암호화](/docs/workspaces/storage-and-encryption)를
참조하세요.

## 기록 지우기 [#clear-history]

- 교환 하나: 컨텍스트 메뉴의 **삭제**.
- 요청 하나의 기록: 기록 목록의 **이 요청의 기록 지우기…**.
- 작업 공간 전체의 기록: 기록 페이지의 **⋯ › 기록 지우기…**. 먼저 “이 작업 공간의 모든 기록을 지우시겠습니까?”라고 묻습니다. 요청은 그대로
  유지되며 이전 응답이 삭제됩니다.

기록을 지워도 요청이나 작업 공간 파일은 절대 건드리지 않습니다.

## 기록이 있는 곳 [#where-history-lives]

작업 공간마다 자체 기록이 있으며, 작업 공간 폴더가 아니라 사용자의 Mac의 Echolot 저장 공간에 보관됩니다. Git으로 공유되지 않으며 팀원의 기록은 팀원
자신의 것입니다. 에이전트는 Echolot을 통해 기록을 읽으며, 자격 증명 헤더와 비밀 값은 가려집니다.

기록을 열 수 없으면 페이지에 “기록을 사용할 수 없음”과 그 이유가 표시됩니다. 전송은 계속 작동하지만, 파일을 열 수 있게 될 때까지 아무것도 기록되지
않습니다.
