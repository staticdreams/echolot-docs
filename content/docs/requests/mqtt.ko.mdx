MQTT 요청은 브로커에 연결하고, 토픽 필터를 구독하며, 메시지를 게시합니다. 작업하는 동안 연결을 유지하며, 로그에는 구독 중인 토픽의 모든 메시지가 표시됩니다. Echolot은
MQTT 3.1.1과 5.0을 지원합니다.

<Shot id="requests-mqtt-log" alt="로컬 브로커에 연결된 Realtime › Warehouse sensors: QoS 1의 warehouses/+/temperature가 있는 구독 탭과 토픽별 온도 측정값이 있는 메시지 로그" />

<Callout title="Alpenglow로 시험해 보기">
  **Realtime › Warehouse sensors**는 문서 저장소의 `examples/servers` 폴더에 있는 `localhost`의 로컬 브로커에 연결합니다(`bun run realtime`).
</Callout>

## 연결 [#connect]

1. **파일 › 새로운 MQTT 요청**을 선택하거나, 사이드바의 **요청** 옆 **+** 메뉴에서 **새로운 MQTT 요청**을 선택합니다.
2. 브로커의 주소를 입력합니다.
3. 주소 앞의 **MQTT** 배지 메뉴에서 프로토콜을 고릅니다. **MQTT 5.0**(기본값) 또는 **MQTT 3.1.1**입니다.
4. **연결**(<kbd>⌘</kbd><kbd>R</kbd>)을 선택합니다. 연결되어 있는 동안에는 **연결 해제**로 표시됩니다.

| 주소 | 연결 방식 | 기본 포트 |
| --- | --- | --- |
| `mqtt://broker` | TCP | 1883 |
| `mqtts://broker` | TLS | 8883 |
| `ws://broker` | WebSocket. 주소에 경로가 없으면 `/mqtt` | 다른 `ws://` 주소와 같음 |
| `wss://broker` | TLS 위의 WebSocket. 주소에 경로가 없으면 `/mqtt` | 다른 `wss://` 주소와 같음 |

주소에는 `{{variables}}`를 쓸 수 있습니다. Alpenglow의 센서 요청은 `mqtt://{{mqttHost}}`를 사용합니다.

편집기의 탭은 **문서**, **구독**, **게시**, **연결**, **인증**, **변수**, **테스트**, **스크립트**, **설정**입니다. TLS 확인, 프록시, 인증서 같은 설정은
[HTTP 요청](/docs/requests/settings)과 같이 적용됩니다.

## 사용자 이름과 비밀번호 [#user-name-and-password]

MQTT의 사용자 이름과 비밀번호는 **인증** 탭에 있는 요청의 **Basic** 인증입니다. 비밀번호는 `{{mqttPassword}}` 같은 [비밀 변수](/docs/workspaces/secrets)에 넣어
키체인에 보관하고 요청 파일에는 남기지 마십시오. 다른 인증과 마찬가지로 폴더나 작업 공간에 한 번 설정할 수 있습니다. 다른 종류의 인증은 MQTT에 적용되지 않습니다.

## 연결 설정 [#the-connection]

**연결** 탭에는 CONNECT의 나머지 항목이 있습니다.

| 필드 | 동작 |
| --- | --- |
| **클라이언트 ID** | 클라이언트의 ID이며 `{{variables}}`를 쓸 수 있습니다. 비워 두면 `echolot-`와 무작위 접미사를 사용합니다 |
| **Clean Start**(5.0) 또는 **Clean Session**(3.1.1) | 이 클라이언트 ID로 브로커가 보관해 둔 구독과 메시지 없이 시작합니다. 기본으로 켜져 있습니다 |
| **Keep Alive** | ping 사이의 간격(초). 0이면 없음. 기본값은 60 |
| **Will** | **연결이 끊기면 Will 메시지 게시**와 함께 **Will 토픽**, **Will 페이로드**, QoS, **Retain**을 지정합니다. 이 클라이언트가 인사 없이 사라졌을 때 브로커가 게시하는 메시지입니다 |

## 구독 [#subscribe]

**구독** 탭에는 요청이 구독하는 토픽 필터가 나열됩니다.

1. 맨 아래 필드에 `warehouses/+/temperature` 같은 필터를 입력합니다. `+`는 한 레벨과, `#`는 나머지 전체와 일치하며 `logs/#`처럼 씁니다.
2. **QoS 0**, **QoS 1**, **QoS 2** 중 하나를 고릅니다.
3. <strong>구독</strong>을 선택하면 한 번 구독하고, <strong>+</strong>를 선택하면 필터를 요청과 함께 저장합니다.

**연결 시 구독**이 체크된 저장된 필터는 요청이 연결될 때마다 구독됩니다. 앱에서, 실행에서, 명령줄에서, 에이전트에서 모두 마찬가지입니다. 연결되어 있는 동안 저장된
필터마다 **구독**과 **구독 해제** 버튼이 있습니다. MQTT 5.0에서는 **No Local**이 이 클라이언트 자신이 게시하는 메시지를 제외합니다.

## 게시 [#publish]

**게시** 탭은 메시지를 보냅니다.

1. 토픽과 페이로드를 입력합니다. 둘 다 `{{variables}}`를 쓸 수 있습니다.
2. QoS를 고르고, 브로커가 이후 구독자를 위해 메시지를 보관하게 하려면 **Retain**을 체크합니다.
3. **게시**를 선택합니다.

<strong>+</strong>를 선택하면 메시지가 요청과 함께 저장됩니다. <strong>실행 시 게시</strong>가 체크된 저장된 메시지는 사용자 없이 요청이 실행될 때 순서대로 게시됩니다.
[실행](/docs/requests/runner)과 명령줄은 연결하고, 사용 설정된 필터를 구독하고, 사용 설정된 메시지를 게시하고, 10초 동안 수신한 다음 닫습니다.

## 메시지 로그 [#the-message-log]

응답 패널의 **메시지** 탭은 세션을 보여 줍니다. 받은 메시지와 게시한 메시지, 구독, 브로커의 확인 응답이 시간순으로 나열되고 가장 최근 항목이 맨 아래에 옵니다.
각 항목에 시간과 크기가 있습니다.

- 메시지에는 토픽, QoS, 보관(retain) 여부, 패킷 ID가 표시됩니다.
- **모든 토픽**은 로그를 하나의 토픽으로 좁힙니다.
- **모두**, **보냄**, **받음**은 방향별로 거르고, **메시지 필터링**은 텍스트로 메시지를 찾습니다.
- **더 보기**는 JSON 페이로드를 보기 좋게 정렬합니다.
- 첫 줄에는 어떤 클라이언트 ID로 어떤 프로토콜로 연결되었는지, 브로커가 이전 세션을 유지했는지가 표시됩니다. 브로커가 연결을 끊으면 로그에 MQTT의 사유와 함께 이유가
  표시됩니다.

QoS 1과 2의 전달은 양방향 모두 자동으로 확인 응답됩니다.

연결이 닫히면 세션은 로그를 응답 본문으로 하여 [기록](/docs/workspaces/history)에 보관되므로 **본문**에 대한 검사가 동작합니다.

## 검사, 캡처, 실행 [#checks-captures-and-runs]

**테스트** 탭의 **메시지 값**, **받은 메시지 수**, **세션 종료** 검사는 받은 메시지를 검사하고, **첫 메시지**와 **마지막 메시지** 캡처는
그 메시지를 읽습니다. 각 페이로드는 JSON으로 읽습니다. 검사나 캡처를 일부 토픽으로 좁히려면 **전체** 필드에
`warehouses/+/temperature` 같은 토픽 필터를 씁니다. **세션 종료**는 브로커가 연결을 끊을 때의 사유 코드를 읽습니다.
[실시간 세션 검사](/docs/requests/scripts-and-tests#checks-on-realtime-sessions)를 참고하십시오.

실행에서는 요청 파일의 `[settings]`에 `stop-after-acks = true`를 지정하면 브로커가 모든 구독과 QoS 1 또는 2의 모든 게시에 확인 응답한
뒤 수신을 멈춥니다. 연결을 거부하는 브로커는 실행에서 상태를 줍니다. 예를 들어 사용자 이름이나 비밀번호가 잘못되면 `401`입니다.
[일찍 수신 멈추기](/docs/requests/websocket-and-sse#stop-listening-early)와
[거부된 연결](/docs/requests/websocket-and-sse#refused-connections)을 참고하십시오.

## MQTT 5.0 [#mqtt-50]

브로커의 사유 코드는 두 버전 모두에서 로그와 연결이 거부될 때 `Success`나 `Not authorized` 같은 이름으로 표시됩니다.

**MQTT 5.0**을 선택했는데 3.1.1만 지원하는 브로커처럼 브로커가 이를 거부하면, Echolot은 MQTT 3.1.1로 다시 연결합니다. 로그의 첫 줄에
어느 프로토콜로 연결했는지 표시됩니다.

**MQTT 5.0**을 선택하면 다음과 같습니다.

- 구독의 **No Local**은 이 클라이언트 자신의 메시지를 제외합니다.
- **Clean Start**가 3.1.1의 **Clean Session**을 대신합니다.
- 저장된 메시지에 콘텐츠 유형(요청 파일의 `content-type`)을 지정할 수 있으며 Content Type 속성으로 전송됩니다.

## 명령줄에서 [#from-the-command-line]

`echolot mqtt subscribe`와 `echolot mqtt publish`는 터미널에서 브로커와 통신하며, 비밀번호는 `ECHOLOT_MQTT_PASSWORD`에 둡니다.
[echolot mqtt](/docs/cli/mqtt)를 참고하십시오.
