Une valeur dynamique est une fonction placée dans `{{ }}` : `{{$uuid}}`, `{{$base64('heidi:alpenglow')}}`,
`{{$responseJSONPath('auth/sign-in', '$.access_token')}}`. Echolot la calcule à l’envoi de la requête. Les valeurs
dynamiques fonctionnent partout où les variables fonctionnent : l’URL, les en-têtes, les corps, les champs d’auth, les
messages et les réglages. Pour savoir comment les choisir et les modifier dans l’app, voir
[valeurs dynamiques](/docs/requests/dynamic-values).

## Les écrire [#writing-them]

- Une valeur dynamique commence par `$` : `{{$timestamp}}`. Sans arguments, les parenthèses sont facultatives.
- Les arguments se placent entre parenthèses, séparés par des virgules : du texte entre guillemets (`'…'` ou `"…"`), des
  nombres, des noms de variables sans guillemets, ou d’autres valeurs dynamiques.
- Les arguments de texte peuvent contenir leurs propres jetons : `{{$base64('{{email}}:{{password}}')}}`. Un `}}` entre
  guillemets ne termine pas le jeton.
- Tout ce qui ne s’analyse pas reste tel que vous l’avez écrit et est signalé : un `{{` isolé ne casse donc jamais une
  requête.

```text
{{$sha256('{{body}}', 'base64')}}
{{$date('yyyy-MM-dd', -86400, 'Europe/Zurich')}}
{{$hmacSha256(apiSecret, $timestamp)}}
```

## Réponses [#responses]

Ces valeurs lisent la dernière réponse d’une autre requête enregistrée, désignée par son chemin (`folder/request`, comme
dans `auth/sign-in`). Chacune accepte un dernier argument facultatif qui indique si cette requête est envoyée d’abord :

| Dernier argument | Signification |
| --- | --- |
| `'if-missing'` (par défaut) | L’envoyer d’abord si elle n’a pas encore de réponse. |
| `'fresh'` | L’envoyer d’abord à chaque fois ; dans une exécution, une fois par exécution. |
| `'latest'` | Ne jamais l’envoyer ; utiliser la dernière réponse. |

| Valeur | Arguments | Ce qu’elle donne |
| --- | --- | --- |
| `$responseJSONPath` | Requête, JSONPath | Une valeur du corps de la réponse, choisie avec JSONPath. `{{$responseJSONPath('auth/sign-in', '$.access_token')}}` |
| `$responseKeyPath` | Requête, chemin de clés | Une valeur choisie avec un chemin de clés comme `data.items.0.id`. `{{$responseKeyPath('orders/list-orders', 'items.0.id')}}` |
| `$responseJq` | Requête, filtre jq | Ce qu’un filtre jq produit à partir du corps ; plusieurs résultats arrivent un par ligne. `{{$responseJq('catalog/list-products', '.items[0].sku')}}` |
| `$responseXPath` | Requête, XPath | Une valeur d’une réponse XML. `{{$responseXPath('echo/xml', '/catalog/product[1]/@sku')}}` |
| `$responseRegex` | Requête, motif | La première correspondance d’une expression régulière dans le corps : son premier groupe s’il y en a un. `{{$responseRegex('echo/html', '<title>(\\w+)</title>')}}` |
| `$responseHeader` | Requête, en-tête | Un en-tête de la réponse. `{{$responseHeader('orders/create-order', 'Location')}}` |
| `$responseCookie` | Requête, cookie | La valeur d’un cookie défini par la réponse. `{{$responseCookie('echo/set-cookie', 'flavour')}}` |
| `$responseStatus` | Requête | Le code d’état. `{{$responseStatus('auth/sign-in')}}` |
| `$responseBody` | Requête | Tout le corps, en texte. `{{$responseBody('auth/who-am-i')}}` |
| `$responseBodyLength` | Requête | La taille du corps en octets. `{{$responseBodyLength('catalog/export')}}` |
| `$response` | Requête, requête de sélection | N’importe laquelle des précédentes, selon la forme de la requête de sélection : un JSONPath (`$.token`), un XPath (`/a/b`, ou `xpath:…`), `regex:…`, `jq:…`, `keypath:…`, `header:Name` ou `cookie:Name`. `{{$response('auth/sign-in', 'header:Content-Type')}}` |

Par exemple, **Who am I** peut prendre son jeton directement dans **Sign in**, en l’envoyant d’abord si nécessaire :

```text
Authorization: Bearer {{$responseJSONPath('auth/sign-in', '$.access_token')}}
```

Une requête qui lit la réponse d’une autre en boucle est refusée, avec la boucle nommée.
Les [captures de réponse](/docs/requests/captures) sont l’autre façon de transmettre des valeurs d’une requête à l’autre.

## Requêtes [#requests]

Ces valeurs lisent une requête telle qu’elle serait envoyée, une fois résolue. Le premier argument est le chemin d’une
requête enregistrée, ou vide (`''`) pour la requête en cours d’envoi.

| Valeur | Arguments | Ce qu’elle donne |
| --- | --- | --- |
| `$requestURL` | Requête | Son URL, résolue. `{{$requestURL('')}}` |
| `$requestMethod` | Requête | Sa méthode. `{{$requestMethod('')}}` |
| `$requestHeader` | Requête, en-tête | Un en-tête, résolu, y compris ce que son auth ajoute. `{{$requestHeader('', 'Content-Type')}}` |
| `$requestQuery` | Requête, paramètre | Un paramètre de requête de son URL, décodé. `{{$requestQuery('', 'page')}}` |
| `$requestBody` | Requête | Son corps, résolu, en texte. `{{$requestBody('')}}` |
| `$requestJSONPath` | Requête, JSONPath | Une valeur de son corps JSON. `{{$requestJSONPath('orders/create-order', '$.lines[0].sku')}}` |
| `$requestJq` | Requête, filtre jq | Ce qu’un filtre jq produit à partir de son corps JSON. `{{$requestJq('', '.lines[0].quantity')}}` |
| `$requestVariable` | Requête, variable | Une variable telle que cette requête la voit. `{{$requestVariable('auth/sign-in', 'email')}}` |

L’usage habituel est de signer une requête avec ce qu’elle envoie :

```text
X-Signature: {{$hmacSha256(apiSecret, $requestBody(''))}}
```

## Hachages et signatures [#hashes-and-signatures]

Chaque hachage prend le texte et, facultativement, la sortie : `'hex'` (par défaut), `'base64'` ou `'base64url'`. Chaque
HMAC prend la clé, le message et, facultativement, la sortie.

| Valeur | Arguments | Ce qu’elle donne |
| --- | --- | --- |
| `$md5` | Texte, sortie | Le MD5 du texte. `{{$md5('alpenglow')}}` |
| `$sha1` | Texte, sortie | Le SHA-1. `{{$sha1('alpenglow')}}` |
| `$sha224` | Texte, sortie | Le SHA-224. |
| `$sha256` | Texte, sortie | Le SHA-256. `{{$sha256($requestBody(''), 'base64')}}` |
| `$sha384` | Texte, sortie | Le SHA-384. |
| `$sha512` | Texte, sortie | Le SHA-512. |
| `$hmacMd5` | Clé, message, sortie | Le HMAC-MD5 du message avec la clé. |
| `$hmacSha1` | Clé, message, sortie | Le HMAC-SHA1. |
| `$hmacSha224` | Clé, message, sortie | Le HMAC-SHA224. |
| `$hmacSha256` | Clé, message, sortie | Le HMAC-SHA256. `{{$hmacSha256(apiSecret, $timestamp)}}` |
| `$hmacSha384` | Clé, message, sortie | Le HMAC-SHA384. |
| `$hmacSha512` | Clé, message, sortie | Le HMAC-SHA512. |

## Temps [#time]

Toutes ces valeurs correspondent au moment de l’envoi de la requête, décalé quand vous donnez un décalage.

| Valeur | Arguments | Ce qu’elle donne |
| --- | --- | --- |
| `$timestamp` | Décalage (facultatif) | Le temps Unix en secondes : `1793525000`. `{{$timestamp(60)}}` vaut dans une minute. |
| `$timestampMs` | Décalage (facultatif) | Le temps Unix en millisecondes : `1793525000123`. |
| `$isoTimestamp` | Décalage (facultatif) | ISO 8601 en UTC, avec les millisecondes : `2026-11-01T09:30:00.123Z`. `{{$isoTimestamp('-90s')}}` vaut il y a 90 secondes. |
| `$httpDate` | aucun | Une date HTTP, pour `Date` ou `If-Modified-Since` : `Sun, 01 Nov 2026 09:30:00 GMT`. |
| `$date` | Format, décalage en secondes (facultatif), fuseau horaire (facultatif) | L’heure dans un motif de date Unicode, décalée du décalage, dans le fuseau horaire (UTC sauf indication). `{{$date('yyyy-MM-dd')}}`, `{{$date('yyyy-MM-dd HH:mm', 3600, 'Europe/Zurich')}}` |

Le décalage de `$timestamp`, `$timestampMs` et `$isoTimestamp` est un nombre de secondes, ou un nombre avec une unité :
`ms`, `s`, `m`, `h`, `d` ou `w`. Un `-` le place dans le passé, un `+` (ou rien) dans le futur : `'-90s'`, `'2h'`,
`'-1d'`, `'1w'`. Écrivez-le entre guillemets, comme du texte ; un simple nombre de secondes peut rester seul, comme
dans `{{$timestamp(-3600)}}`. Un décalage qui n’en est pas un échoue avec un message qui dit quoi écrire.

## Aléatoire [#random]

Une nouvelle valeur à chaque envoi, sauf `$sameUUID`.

| Valeur | Arguments | Ce qu’elle donne |
| --- | --- | --- |
| `$uuid` | aucun | Un UUID aléatoire, en minuscules. Aussi `$guid` et `$randomUUID`. `{{$uuid}}` |
| `$sameUUID` | Nom | Un UUID aléatoire créé une fois et redonné partout où le même nom le demande : une fois par exécution (chaque itération a le sien), et hors exécution une fois par fenêtre, ou une fois par commande en ligne de commande. `{{$sameUUID('order')}}` |
| `$randomInt` | Minimum, maximum | Un nombre entier entre les deux, bornes comprises. Un argument est le maximum, à partir de 0 ; aucun donne 0 à 1000. `{{$randomInt(1, 5)}}` |
| `$randomString` | Longueur, caractères (facultatif) | Des caractères aléatoires, 16 sauf indication (jusqu’à 4096) : des lettres et des chiffres, ou les caractères donnés. `{{$randomString(8, 'ABCDEF0123456789')}}` |
| `$randomHex` | Octets | Des octets aléatoires en hexadécimal, 16 sauf indication (jusqu’à 2048) ; deux fois plus de chiffres. `{{$randomHex(8)}}` |

**Create order** d’Alpenglow envoie `Idempotency-Key: {{$uuid}}` : chaque commande qu’il passe est donc nouvelle. Là
où plusieurs requêtes d’une exécution doivent envoyer la même clé, comme une requête et sa nouvelle tentative ou une
création et la mise à jour qui la suit, donnez-leur `{{$sameUUID('order')}}` : chaque exécution reçoit une nouvelle
clé, et chaque requête qui nomme `order` l’envoie.

## Données fictives [#fake-data]

Des valeurs inventées pour les corps de requête, les données de test et les [routes de mock](/docs/mocks/routes#bodies-with-fake-data) :
noms, adresses, entreprises, prix, dates, lorem ipsum et plus, nouvelles à chaque envoi. Les noms sont les variables
dynamiques de Postman : les collections qui les utilisent envoient donc de vraies valeurs ici. Dans la liste `{{`, elles
sont sous **Données fictives**, par catégorie.

Les arguments sont facultatifs ; les nombres vont de -10^15 à 10^15. Les corps de mock peuvent aussi utiliser `$uuid`
(sous la forme `$randomUUID`), `$randomInt`, `$randomString`, `$randomHex`, `$timestamp`, `$timestampMs` et
`$isoTimestamp`, de [Aléatoire](#random) et de [Temps](#time), les valeurs de temps avec leurs décalages. Depuis
Terminal, [`echolot fake`](/docs/cli/fake) remplit un modèle avec elles.

## Valeurs dynamiques et agents [#dynamic-values-and-agents]

Quand un agent IA envoie une requête (via le serveur MCP d’Echolot ou l’Assistant), `$env` ne donne rien, et `$file` ne lit
que des fichiers situés dans l’espace de travail. Les valeurs secrètes n’arrivent jamais jusqu’à l’agent. Voir
[agents](/docs/ai/agents).
