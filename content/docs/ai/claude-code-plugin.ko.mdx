Echolot 플러그인은 Claude Code에 Echolot을 다루는 방법을 알려 줍니다. Echolot의 [MCP 서버](/docs/ai/agents)가 에이전트에게
도구를 제공한다면, 플러그인은 Claude에게 그 도구를 언제 어떻게 쓰는지 알려 줍니다. 어떤 프로토콜에 어떤 도구를 쓰는지,
작업 공간을 프로젝트의 어디에 두는지, 자격 증명이 대화에 들어가지 않게 하려면 어떻게 하는지 같은 것입니다.
플러그인이 있으면 개발하는 동안 Claude가 보낸 요청은 세션이 끝나면 사라지는 `curl` 명령이 아니라, 작업 공간에 저장되고,
검사를 거치고, 기록에 남으며, 사용자가 앱에서 열어 볼 수 있는 요청이 됩니다.

## 플러그인이 추가하는 것 [#what-the-plugin-adds]

플러그인은 `echolot`이라는 스킬 하나와 그 참조 파일로 이루어져 있습니다. Claude는 작업이 프로젝트의 API와 관련될 때
이 스킬을 불러옵니다.

| 구성 요소 | Claude에게 제공하는 것 |
| --- | --- |
| 스킬 | Echolot을 언제 쓰는지, 프로젝트를 어떻게 설정하는지, 모든 요청에서 반복하는 순서(환경, 만들기, 보내기, 검사, 보고), 승인이 거부되면 어떻게 하는지 |
| 설정 참조 | Echolot 설치, MCP 서버 연결, 정책, 도구 모음, 비밀 값 |
| 요청 파일 참조 | 모든 종류의 요청(HTTP, GraphQL, WebSocket, Socket.IO, MQTT, gRPC, MCP)에 대한 작업 공간의 TOML |
| 레시피 | 스모크 테스트 모음, OpenAPI 문서, 페이지 매김, 실시간 확인, 모의 서버, 플로, MCP 서버 테스트, CI |
| 스크립트 | `local`과 `production` 환경이 있는 빈 작업 공간을 만듭니다 |

플러그인에는 스스로 실행되는 코드도 서버도 없습니다. Claude는 여전히 MCP 서버와 [명령줄 도구](/docs/cli)를 통해
Echolot에 접근하며, [외부 에이전트](/docs/ai/agents)에서 설명하는 승인과 제한이 그대로 적용됩니다.

## 설치하기 전에 [#before-you-install]

다음이 필요합니다.

- 플러그인을 지원하는 **Claude Code**.
- `PATH`에 있는 **Echolot의 명령줄 도구**. `echolot --version`이 작동해야 합니다.
  [명령줄 도구](/docs/cli)를 참조하십시오.

<Edition only="appstore">
  App Store 버전에는 앱 안에 명령줄 도구가 없습니다. 명령줄 도구는 따로 설치합니다(**설정 › 에이전트**의
  **명령줄 도구 받기**에서 다운로드로 이동합니다). 플러그인은 이 도구로도 똑같이 작동합니다.
</Edition>

## 플러그인 설치 [#install-the-plugin]

<Steps>
<Step>
Claude Code에서 Echolot 마켓플레이스를 추가합니다.

```text
/plugin marketplace add staticdreams/echolot-claude-plugin
```
</Step>
<Step>
마켓플레이스에서 플러그인을 설치합니다.

```text
/plugin install echolot@echolot
```
</Step>
<Step>
아래 설명대로 Claude에게 프로젝트를 설정해 달라고 요청합니다. 플러그인은 한 번만 설치하고, 프로젝트는 각각 한 번씩 설정합니다.
</Step>
</Steps>

새 버전을 받으려면 `/plugin marketplace update echolot`을 실행합니다. 플러그인을 제거하려면
`/plugin uninstall echolot@echolot`을 실행합니다.

## 프로젝트 설정 [#set-up-a-project]

프로젝트 폴더에서 Claude에게 다음과 같이 요청합니다.

```text
이 프로젝트에 Echolot을 설정해 줘
```

그러면 Claude는 다음 작업만 하고, 그 밖의 일은 하지 않습니다.

1. `echolot`이 실행되는지 확인합니다.
2. 프로젝트에서 작업 공간, 즉 이름이 `.echolot`으로 끝나는 폴더를 찾습니다. 없으면 프로젝트 루트에 `local` 환경과
   `production` 환경이 있는 작업 공간을 만들고, 프로젝트가 사용하는 호스트를 변수로 추가합니다.
3. 질문을 하나 합니다. Claude의 변경 사항을 Echolot 앱에서 승인할지, 아니면 사용자 없이 작업하게 둘지입니다.
   [승인 또는 무인 실행](#approvals-or-unattended)을 참조하십시오.
4. 프로젝트에 Echolot의 MCP 서버를 등록합니다. 이때 프로젝트 루트에 `.mcp.json`이 작성됩니다.

   ```sh
   claude mcp add --scope project echolot -- echolot mcp serve ./alpenglow.echolot --toolsets all --env local
   ```

5. 프로젝트의 `CLAUDE.md`에 API 호출이 Echolot을 거친다는 짧은 메모를 추가하겠다고 제안합니다.

그런 다음 멈추고, 사용자가 다음에 할 일을 알려 줍니다.

1. 앱에서 승인하기로 했다면 Echolot에서 작업 공간을 열고, **설정 › 에이전트**에서
   **에이전트가 열린 작업 공간을 사용하도록 허용**을 켠 다음, **에이전트용 도구** 아래에서 원하는 도구 모음을 켭니다.
   다른 도구 모음을 켜기 전까지 앱은 **요청**과 **플로**를 제공합니다.
2. Claude Code를 다시 시작하거나 `/mcp`를 실행하고, 프로젝트의 서버를 승인합니다.

작업 공간과 `.mcp.json`을 커밋하십시오. 둘 다 비밀 값을 담고 있지 않으며, 팀원은 저장소에서 같은 설정을 받습니다.

## 승인 또는 무인 실행 [#approvals-or-unattended]

MCP 서버는 시작할 때 어떻게 실행될지 정합니다.

| 실행 방식 | 일어나는 일 |
| --- | --- |
| 작업 공간이 Echolot에서 열려 있고 에이전트가 켜져 있는 경우 | Claude의 호출이 앱에서 실행됩니다. 변경이나 데이터를 변경할 수 있는 전송은 시트로 사용자에게 묻습니다. 요청이 사이드바에 하나씩 나타나는 것을 볼 수 있습니다. |
| 단독 실행, `--policy permissive` 사용 | 전송과 변경이 묻지 않고 실행됩니다. 삭제는 거부되며, 보호된 환경과 새로운 호스트로의 전송도 거부됩니다. |
| 단독 실행, 정책 지정 없음 | 읽기와 안전한 전송이 실행됩니다. 그 밖의 것은 모두 거부됩니다. |

앱에서 승인하는 방식은 개발하는 동안에 알맞습니다. Claude가 하는 일을 지켜보고 거부할 수 있기 때문입니다. 무인 실행은
지켜보고 있고 싶지 않은 긴 작업에 알맞습니다. 한 방식에서 다른 방식으로 바꾸려면 Echolot에서 작업 공간을 열거나 닫고
`/mcp`를 실행해 다시 연결합니다. 정책은 [단독 실행](/docs/ai/agents#on-its-own)을 참조하십시오.

## 요청할 수 있는 것 [#what-to-ask-for]

Echolot을 언급할 필요는 없습니다. 프로젝트에 작업 공간이 있으면 Claude는 그 프로젝트의 API를 호출할 때 작업 공간을 사용합니다.

| 사용자의 요청 | Claude가 Echolot에서 하는 일 |
| --- | --- |
| “데모 사용자로 로그인해서 내 주문 목록을 보여 줘” | 비밀번호를 비밀 값으로 저장하고, 응답의 토큰을 보관하는 로그인 요청을 저장한 다음, 그 토큰으로 목록 요청을 보냅니다. 토큰은 대화에 전달되지 않습니다. |
| “주문 API의 스모크 테스트 모음을 만들어 줘” | 목록, 조회, 만들기, 업데이트 요청과 각각의 실패 사례 하나씩을 검사와 함께 담은 폴더를 만들고, 요청이 보관하는 값으로 서로 연결합니다. 그런 다음 폴더를 실행하고 무엇이 실패했는지 보고합니다. |
| “이 페이지에는 아직 없는 위시리스트 API가 필요해” | OpenAPI 문서로, 또는 직접 만든 경로와 가짜 데이터로 모의 서버를 만들고, 그 경로에 대한 요청을 만듭니다. |
| “이 엔드포인트는 왜 얼마 지나면 실패하지?” | 요청을 여러 번 다시 보내고, 기록의 교환을 비교한 다음, 문제가 API에 있는지 테스트에 있는지 알려 줍니다. |
| “주문 이벤트가 WebSocket으로 도착하는지 확인해 줘” | 세션을 열고, 다른 요청으로 주문을 넣은 다음, 세션이 받은 내용을 읽습니다. |
| “우리 MCP 서버의 도구를 테스트해 줘” | 서버를 추가하고 확인한 다음, 도구마다 결과에 대한 검사가 있는 호출을 저장합니다. |
| “로그인하고, 주문을 만들고, 배송될 때까지 폴링해 줘” | 그 블록들로 플로를 그립니다. 사용자가 승인하면 실행됩니다. |
| “CI에서 API 테스트를 실행해 줘” | 파이프라인에 넣을 `echolot run` 명령을 보고서 설정, 필요한 비밀 값의 이름과 함께 알려 줍니다. |

어느 요청이든 작업 공간에 무언가를 남깁니다. 요청, 검사, 모의 서버나 플로이며, Echolot에서 열고, 변경하고, 다시 실행할 수
있습니다.

## Claude가 하지 않는 일 [#what-claude-does-not-do]

스킬은 Claude가 다음 규칙을 지키게 합니다.

- **자격 증명을 파일이나 대화에 남기지 않습니다.** 사용자가 알려 준 비밀번호나 키는 곧바로 비밀 변수에 들어가고,
  그 뒤로는 `{{변수 이름}}`만 나타납니다. 토큰은 Echolot이 로그인 응답에서 보관하며 Claude를 거치지 않습니다.
- **삭제하지 않습니다.** 사용자가 그 항목을 삭제해 달라고 요청한 경우는 예외입니다.
- **보호된 환경이나 프로덕션 환경을 대상으로 테스트하지 않습니다.** 사용자가 요청한 경우는 예외입니다. 보호된 환경으로의
  전송은 항상 사용자에게 묻습니다.
- **스크립트를 제멋대로 쓰지 않습니다.** 스크립트는 사용자가 신뢰해야 하는 코드입니다. Claude는 스크립트를 제안하고 어디에
  들어가는지 알려 주며, Echolot은 실행하기 전에 사용자에게 묻습니다.
- **요청한 것보다 더 하지 않습니다.** “설정해 줘”는 설정만을 뜻합니다. “이 엔드포인트를 테스트해 줘”는 그 엔드포인트의
  요청과 검사를 뜻하며, 테스트 모음 전체가 아닙니다.
- **말없이 도구를 바꾸지 않습니다.** 승인이 거부되거나 도구가 없으면 Claude는 무엇이 필요한지 알려 주고 기다립니다.
  `curl`로 대신하지 않습니다.

## 문제 해결 [#troubleshooting]

- **Claude가 여전히 `curl`을 씁니다.** 플러그인이 설치되어 있는지(`/plugin`), 프로젝트에 작업 공간이 있는지,
  `/mcp`에 `echolot` 서버가 연결된 것으로 나오는지 확인하십시오. 모두 그렇다면 `CLAUDE.md`에 메모를 추가하십시오. Claude에게
  “CLAUDE.md에 Echolot 메모를 추가해 줘”라고 요청하면 됩니다.
- **변경이 거부되는데 아무것도 묻지 않습니다.** 서버가 단독으로 실행 중입니다. Echolot에서 작업 공간을 열고
  **에이전트가 열린 작업 공간을 사용하도록 허용**을 켠 다음 `/mcp`를 실행해 다시 연결하십시오. 또는 Claude에게 서버를
  permissive 정책으로 바꿔 달라고 요청하십시오.
- **Claude가 도구가 없다고 합니다.** 해당 도구 모음이 꺼져 있습니다. **설정 › 에이전트**의 **에이전트용 도구** 아래에서 켜고
  다시 연결하십시오.
- **Claude가 작성한 요청이 나타나지 않습니다.** 단독으로 실행되는 서버는 시작할 때 작업 공간을 읽습니다. `/mcp`를 실행해
  `echolot`을 다시 연결하십시오. 앱을 거치면 새 요청은 바로 나타납니다.
