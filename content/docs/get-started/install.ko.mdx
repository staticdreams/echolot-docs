Echolot은 [echolot.dev](https://echolot.dev)에서 직접 내려받을 수 있습니다. 이 페이지는 해당 버전을 설명합니다. 같은 코드로 만든 Mac App
Store 버전도 있으며, [에디션](/docs/get-started/editions)에서 두 버전을 비교합니다.

## 요구 사항 [#requirements]

- macOS 15 이상.
- Apple 실리콘이 탑재된 Mac.
- 일부 기능에는 더 최신 macOS가 필요합니다. 어시스턴트가 Apple의 온디바이스 모델을 쓰려면 macOS 26이, HTTP/3에는 macOS 27이 필요합니다.
  나머지 기능은 모두 macOS 15에서 작동합니다.

## 내려받기 및 설치 [#download-and-install]

<Steps>
<Step>

[echolot.dev](https://echolot.dev)를 열고 다운로드를 선택합니다. 최신 릴리스가 있는
[GitHub](https://github.com/staticdreams/echolot-public/releases) 페이지로 이동하며, 모든 릴리스의 파일이 그곳에 남아 있습니다.

| 파일 | 설명 |
| --- | --- |
| `Echolot-<version>.dmg` | 디스크 이미지에 담긴 앱입니다. 이 파일을 사용합니다. |
| `Echolot-<version>.zip` | 같은 앱을 압축한 파일입니다. |
| `echolot-<version>-macos.zip` | 앱이 없는 Mac을 위한 명령줄 도구 단독 파일입니다. |
| `Echolot-<version>.mcpb` | Claude Desktop을 작업 공간에 연결하는 확장 프로그램입니다. [에이전트](/docs/ai/agents)를 참고하십시오. |

</Step>
<Step>

디스크 이미지를 열고 **Echolot**을 옆에 있는 **응용 프로그램** 폴더로 드래그합니다.

</Step>
<Step>

응용 프로그램 폴더에서 Echolot을 엽니다. 앱은 개발자가 서명하고 Apple이 공증했으므로, 인터넷에서 내려받은 앱을 열겠느냐는 확인은 macOS가 한 번만
묻습니다.

</Step>
</Steps>

## 처음 실행 [#first-launch]

Echolot을 열면 환영 윈도우가 나타납니다.

<Shot id="get-started-welcome" alt="새로운 작업 공간, 작업 공간 열기, 예제 열기와 최근 작업 공간 목록이 있는 환영 윈도우" />

| 선택 항목 | 동작 |
| --- | --- |
| **새로운 작업 공간…** | 작업 공간을 만듭니다. 작업 공간은 `.echolot`으로 끝나는 폴더이며(이름은 `My API.echolot`로 시작합니다), 원하는 위치에 저장합니다. |
| **작업 공간 열기…** | 기존 `.echolot` 폴더를 엽니다. |
| **예제 열기** | 공개 API, 리디렉션, 큰 페이로드 같은 예제 요청이 담긴 작업 공간을 엽니다. Echolot은 이 작업 공간을 처음 열 때 자체 데이터 폴더에 만듭니다. |

연 작업 공간은 **최근 작업 공간** 아래에 나타나며, 하나를 클릭하면 다시 열립니다. 작업 공간마다 별도의 윈도우에서 열리고, Echolot을 다시
시작하면 윈도우도 해당 작업 공간과 함께 돌아옵니다.

처음 여는 작업 공간 윈도우에서는 1분짜리 [안내 투어](/docs/get-started/tour)를 제안합니다. **도움말 › 투어 보기**를 선택하면 투어를 다시
시작합니다. Echolot은 Mac의 언어가 지원되면 그 언어로 표시되며, [설정](/docs/settings#general)에서 바꿀 수 있습니다.

여기서부터 [첫 번째 요청을 보내거나](/docs/get-started/first-request), 이미 가지고 있는 컬렉션을 [가져옵니다](/docs/get-started/importing).

## 업데이트 [#updates]

직접 내려받은 버전은 스스로 업데이트됩니다. 하루에 한 번 GitHub에 새 릴리스가 있는지 확인하고, 설치하기 전에 먼저 묻습니다. 업데이트는
서명되어 있으며, Echolot은 개발자가 서명한 업데이트만 설치합니다. 업데이트를 설치하면 앱이 교체되고, 앱 안에 들어 있는 명령줄 도구도 함께 교체됩니다.

- <strong>Echolot › 업데이트 확인…</strong>은 바로 확인합니다.
- **설정 › 일반 › 업데이트**에서 다음 항목을 고를 수 있습니다.

| 설정 | 의미 |
| --- | --- |
| **자동으로 업데이트 확인** | 하루에 한 번 확인합니다. 기본적으로 켜져 있습니다. |
| **자동으로 업데이트 다운로드 및 설치** | 묻지 않고 설치합니다. 위의 설정이 켜져 있어야 합니다. |
| **마지막 확인** | 마지막으로 확인한 시각이며, **지금 확인** 버튼이 함께 있습니다. |

업데이트한 뒤에도 저절로 열리는 것은 없습니다. 윈도우 오른쪽 위 버튼들 중 맨 앞에 **새로운 기능** 버튼(반짝이 아이콘과 점)이 나타나며,
클릭하면 릴리스 노트를 읽을 수 있고 **다음 업데이트까지 가리기**를 선택할 수도 있습니다. **도움말 › Echolot의 새로운 기능**은 모든 릴리스의
노트를 언제든 보여 주며, [새로운 기능](/docs/whats-new) 페이지도 마찬가지입니다.

<Shot id="get-started-whats-new" alt="페이지 헤더에서 열린 새로운 기능 버튼과 방금 설치한 릴리스의 노트" />

<Edition only="appstore">
  App Store 버전은 App Store가 최신 상태로 유지합니다. **업데이트 확인…** 항목이 없으며, 설정 › 일반 › 업데이트에도 그렇게 안내되어 있습니다.
</Edition>

## 베타 빌드는 만료됩니다 [#beta-builds-expire]

Echolot은 공개 베타 중이며, 출시된 베타 빌드는 각각 릴리스 후 30일이 지나면 만료됩니다. Echolot은 그 전에 스스로 업데이트하므로, 자동 확인을 켜 두면
알아차리지 못할 것입니다. 개발자는 빌드를 더 일찍 종료하거나(예를 들어 심각한 버그가 있는 빌드) 기간을 연장할 수도 있습니다. 이는 Echolot이 실행할 때와
하루에 한 번 읽는, 서명된 상태 파일을 통해 이루어집니다.

빌드가 만료되면 Echolot은 윈도우를 열기 전에 **이 베타가 만료됨** 알림창을 한 번 표시합니다. 알림창에는 버전과 빌드, 종료된 날짜가 나오고, 더 새로운
베타를 echolot.dev에서 받을 수 있다고 안내합니다. **확인**을 누르면 저장하지 않은 수정 사항을 기록한 뒤 Echolot이 종료됩니다. 실행 중에 만료되는 빌드도
같은 알림창을 표시합니다. [echolot.dev](https://echolot.dev)에서 최신 릴리스를 내려받아 이전 버전 위에 설치하십시오.

그대로 유지되는 것은 다음과 같습니다.

- **작업 공간.** 일반 파일이므로, 다음 빌드가 그대로 엽니다.
- **명령줄 도구**는 앱 안에 있든 따로 내려받았든 만료되지 않으므로, CI는 계속 실행됩니다.
- Finder에서 작업 공간을 보는 **훑어보기**도 계속 작동합니다.

만료된 빌드의 단축어 동작은 오류와 함께 실패하며 아무것도 보내지 않습니다.

Mac의 시계를 되돌려도 만료된 빌드는 되살아나지 않습니다. 시계가 Echolot이 이미 확인한 날짜보다 하루 넘게 뒤처져 있으면, 알림창에 이 Mac의 날짜가
올바르지 않은 것 같다고 표시됩니다. 날짜와 시간을 설정하거나 더 새로운 빌드를 받으십시오.

<Edition only="direct">
  직접 내려받은 버전의 베타 빌드만 만료됩니다. App Store 버전은 만료되지 않습니다. 베타는 TestFlight를 통해 배포되기 때문입니다.
</Edition>

## 명령줄 도구 설치 [#install-the-command-line-tool]

직접 내려받은 버전은 `echolot` 명령줄 도구를 앱 안에 포함하고 있습니다. 터미널에서 쓰려면 PATH에 추가합니다.

1. <strong>Echolot › 명령줄 도구 설치…</strong>를 선택하거나, <strong>설정 › 일반</strong>을 열고 <strong>명령줄 도구</strong> 아래에서 <strong>명령줄 도구 설치…</strong>를 선택합니다.
2. Echolot이 `/opt/homebrew/bin` 또는 `/usr/local/bin`에 `echolot`이라는 링크를 만듭니다. 두 폴더 모두 쓸 수 없으면 macOS가 관리자 암호를 묻습니다.
3. 새 터미널 윈도우를 열고 `echolot --help`를 입력합니다.

```sh
echolot --version
echolot send https://demo.echolot.dev/v1/products -i
```

**설정 › 일반 › 명령줄 도구**에는 내장 도구의 위치와 PATH에 있는지 여부가 표시되며, **다시 설치**와 **제거** 버튼이 있습니다. Echolot이 만들지 않은
`echolot` 파일이 방해가 되면 Echolot이 교체하기 전에 묻고, 이전 파일은 휴지통으로 이동합니다. 링크가 앱 안을 가리키므로 도구는 앱과 함께 업데이트됩니다.

도구와 그 명령은 [명령줄 도구](/docs/cli)에서 설명합니다.

<Edition only="appstore">
  App Store 버전에는 명령줄 도구가 들어 있지 않습니다. 릴리스 페이지에서 도구를 따로 설치하십시오(`echolot-<version>-macos.zip`).
  [명령줄 도구](/docs/cli)를 참고하십시오.
</Edition>

## 제거 [#uninstall]

1. 명령줄 도구를 설치했다면, 먼저 **설정 › 일반**을 열고 **명령줄 도구** 아래에서 **제거**를 선택합니다.
2. Echolot을 종료하고 응용 프로그램 폴더에서 휴지통으로 드래그합니다.
3. Echolot 자체 데이터(저장된 응답, 기록, 충돌 보고서, 예제 작업 공간)도 제거하려면, 앱을 삭제하기 전에 **설정 › 정보**를 열고 **응답 및 기록** 옆의
   **Finder에서 보기**를 선택한 다음 그 `Echolot` 폴더를 삭제합니다. 경로는 `~/Library/Application Support/Echolot`입니다.
4. 비밀 값, 모델 키, 저장 키는 로그인 키체인에 있으며, 이름이 `Echolot`으로 시작하는 항목입니다(`Echolot secret …`, `Echolot model API key`).
   제거하려면 키체인 접근을 열고 `Echolot`을 검색합니다. 비밀 값은 Echolot이나 명령줄 도구의 다른 사본이 더 이상 필요로 하지 않을 때만 삭제하십시오.

작업 공간은 건드리지 않습니다. 저장한 위치에 그대로 남아 있습니다.
