Echolotは[echolot.dev](https://echolot.dev)から直接ダウンロードできます。このページではそのエディションを説明します。
同じコードから作られたMac App Store版もあります。2つの比較は[エディション](/docs/get-started/editions)にあります。

## 動作条件 [#requirements]

- macOS 15以降。
- Appleシリコンを搭載したMac。
- 一部の機能にはより新しいmacOSが必要です。アシスタントのAppleオンデバイスモデルにはmacOS 26、HTTP/3にはmacOS 27が必要です。それ以外はすべてmacOS 15で動作します。

## ダウンロードとインストール [#download-and-install]

<Steps>
<Step>

[echolot.dev](https://echolot.dev)を開いて、ダウンロードを選びます。最新のリリースがある[GitHub](https://github.com/staticdreams/echolot-public/releases)に移動します。リリースごとに、次のファイルが用意されています。

| ファイル | 内容 |
| --- | --- |
| `Echolot-<version>.dmg` | ディスクイメージに入ったアプリ。通常はこれを使います。 |
| `Echolot-<version>.zip` | 同じアプリをzipにしたもの。 |
| `echolot-<version>-macos.zip` | コマンドラインツール単体。アプリがないMac用です。 |
| `Echolot-<version>.mcpb` | Claude Desktopをワークスペースに接続する拡張機能。[エージェント](/docs/ai/agents)を参照してください。 |

</Step>
<Step>

ディスクイメージを開き、**Echolot**を横にある**アプリケーション**フォルダにドラッグします。

</Step>
<Step>

アプリケーションフォルダからEcholotを開きます。アプリは開発元によって署名され、Appleによって公証されているため、macOSが確認するのは、インターネットからダウンロードしたアプリを開くかどうかの1回だけです。

</Step>
</Steps>

## 初回起動 [#first-launch]

Echolotは、ようこそウインドウで始まります。

<Shot id="get-started-welcome" alt="ようこそウインドウ。新規ワークスペース、ワークスペースを開く、サンプルを開くの各ボタンと、最近使ったワークスペースの一覧" />

| 選択肢 | 動作 |
| --- | --- |
| **新規ワークスペース…** | ワークスペースを作成します。保存先は自由で、`.echolot`で終わるフォルダになります（名前は`My API.echolot`から始まります）。 |
| **ワークスペースを開く…** | 既存の`.echolot`フォルダを開きます。 |
| **サンプルを開く** | サンプルのリクエストが入った、用意済みのワークスペースを開きます。公開API、リダイレクト、サイズの大きいペイロードなどです。Echolotは初回に、自身のデータフォルダ内に作成します。 |

開いたワークスペースは**最近使ったワークスペース**に表示されます。クリックするともう一度開きます。ワークスペースはそれぞれ専用のウインドウで開き、Echolotを再び起動すると、ウインドウはワークスペースとともに復元されます。

最初に開いたワークスペースのウインドウでは、1分間の[ガイドツアー](/docs/get-started/tour)が案内されます。**ヘルプ › ツアーを表示**でもう一度開始できます。
Echolotは、対応していればMacの言語で表示されます。変更は[設定](/docs/settings#general)で行います。

ここから、[最初のリクエストを送信](/docs/get-started/first-request)するか、すでにあるコレクションを[読み込み](/docs/get-started/importing)ます。

## アップデート [#updates]

直接ダウンロード版は自動でアップデートします。1日に1回、GitHubに新しいリリースがあるかを確認し、インストールする前に確認を求めます。アップデートは署名されており、Echolotは開発元が署名したアップデートだけをインストールします。
アップデートをインストールすると、アプリが置き換わり、アプリ内のコマンドラインツールも置き換わります。

- <strong>Echolot › アップデートを確認…</strong>で、すぐに確認します。
- **設定 › 一般 › アップデート**に、次の選択肢があります。

| 設定 | 意味 |
| --- | --- |
| **アップデートを自動的に確認** | 1日に1回確認します。デフォルトでオンです。 |
| **アップデートを自動的にダウンロードしてインストール** | 確認なしでインストールします。上の設定がオンである必要があります。 |
| **最終確認** | 最後に確認した日時と、**今すぐ確認**。 |

アップデート後、自動で開くものはありません。ウインドウの右上にあるボタンの先頭に、**新機能**ボタン（きらめきのアイコンとドット）が表示されます。クリックするとリリースノートを読めます。**次のアップデートまで非表示**を選ぶこともできます。
**ヘルプ › Echolotの新機能**ではいつでもすべてのリリースのノートを表示でき、[新機能](/docs/whats-new)でも読めます。

<Shot id="get-started-whats-new" alt="ページヘッダーの新機能ボタンを開いた状態。インストールしたばかりのリリースのノートが表示されている" />

<Edition only="appstore">
  App Store版は、App Storeが最新の状態に保ちます。<strong>アップデートを確認…</strong>の項目はなく、設定 › 一般 › アップデートにもその旨が表示されます。
</Edition>

## ベータ版は期限が切れる [#beta-builds-expire]

Echolotは公開ベータ中で、リリースされたベータ版のアプリは、リリースから30日で期限が切れます。
それまでにEcholotは自動でアップデートされるため、自動確認がオンなら気づくことはありません。
開発者は、署名されたステータスファイル（Echolotが起動時と1日に1回読み取ります）を通じて、ビルドの期限を早めたり（たとえば重大な不具合があるものを）、延長したりすることもできます。

ビルドの期限が切れると、どのウインドウも開く前に、**このベータ版は有効期限が切れました**というアラートが1回表示されます。バージョンとビルド、期限が切れた日、そしてecholot.devに新しいベータ版があることが示されます。
**OK**を押すと、未保存の編集を書き込んでからEcholotが終了します。実行中に期限が切れた場合も、同じアラートが表示されます。
[echolot.dev](https://echolot.dev)から最新のリリースをダウンロードし、古いものに上書きインストールしてください。

影響を受けないもの：

- **ワークスペース。** 通常のファイルなので、次のビルドでもそのまま開けます。
- **コマンドラインツール**は、アプリ内のものも単体でダウンロードしたものも期限がなく、CIは動き続けます。
- Finderでのワークスペースの**クイックルック**プレビューは、引き続き使えます。

期限が切れたビルドのショートカットのアクションは、エラーで失敗し、何も送信しません。

Macの時計を戻しても、期限が切れたビルドは復活しません。時計が、Echolotがすでに確認した日付より1日以上遅れている場合は、このMacの日付がおかしいというアラートが表示されます。日付と時刻を設定するか、新しいビルドを入手してください。

<Edition only="direct">
  期限が切れるのは、直接ダウンロード版のベータ版だけです。App Store版は期限が切れません。ベータ版はTestFlightで配布されます。
</Edition>

## コマンドラインツールをインストールする [#install-the-command-line-tool]

直接ダウンロード版には、アプリの中に`echolot`コマンドラインツールが含まれています。ターミナルで使うには、PATHに追加します。

1. <strong>Echolot › コマンドラインツールをインストール…</strong>を選びます。または<strong>設定 › 一般</strong>を開き、<strong>コマンドラインツール</strong>の<strong>コマンドラインツールをインストール…</strong>を選びます。
2. Echolotは、`echolot`という名前のリンクを`/opt/homebrew/bin`または`/usr/local/bin`に作成します。どちらのフォルダにも書き込めない場合は、macOSが管理者のパスワードを求めます。
3. ターミナルの新しいウインドウを開いて、`echolot --help`と入力します。

```sh
echolot --version
echolot send https://demo.echolot.dev/v1/products -i
```

**設定 › 一般 › コマンドラインツール**には、内蔵ツールの場所とPATHに入っているかどうかが表示され、**再インストール**と**削除**があります。
Echolotが作成したものではない`echolot`という名前のファイルが邪魔をしている場合は、置き換える前に確認が表示され、古いファイルはゴミ箱に入ります。リンクはアプリの中を指しているため、ツールはアプリとともにアップデートされます。

ツールとそのコマンドは、[コマンドラインツール](/docs/cli)で説明しています。

<Edition only="appstore">
  App Store版には、コマンドラインツールが含まれていません。リリースページからツールを単体でインストールしてください（`echolot-<version>-macos.zip`）。[コマンドラインツール](/docs/cli)を参照してください。
</Edition>

## アンインストール [#uninstall]

1. コマンドラインツールをインストールした場合は、先に**設定 › 一般**を開き、**コマンドラインツール**の**削除**を選びます。
2. Echolotを終了し、アプリケーションフォルダからゴミ箱にドラッグします。
3. Echolot自身のデータ（保存済みのレスポンス、履歴、クラッシュレポート、サンプルワークスペース）も削除する場合は、アプリを削除する前に**設定 › 情報**を開き、**レスポンスと履歴**の横の**Finderに表示**を選んで、その`Echolot`フォルダを削除します。場所は`~/Library/Application Support/Echolot`です。
4. シークレット、モデルキー、ストレージキーは、ログインキーチェーンの、名前が`Echolot`で始まる項目にあります（`Echolot secret …`、`Echolot model API key`）。削除するには、キーチェーンアクセスを開いて`Echolot`を検索します。
   シークレットは、Echolotまたはそのコマンドラインツールのどのコピーもそれらをもう必要としない場合にだけ削除してください。

ワークスペースは影響を受けません。保存した場所にそのまま残ります。
