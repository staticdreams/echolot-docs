---
title: "Claude Code 插件"
description: "为 Claude Code 安装 Echolot 插件，让 Claude 在你开发时经由 Echolot 测试、调试、模拟和自动化项目的 API。"
---

Echolot 插件教 Claude Code 如何使用 Echolot。Echolot 的 [MCP 服务器](/docs/ai/agents)为智能体提供工具；
插件则告诉 Claude 何时使用这些工具、怎样使用：哪种协议用哪个工具，工作区放在项目的什么位置，怎样让凭据不进入对话。
有了它，Claude 在你开发时发出的请求会存储在你的工作区中，经过检查，留在历史记录里，你可以在 App 中打开，
而不是一条会话结束就消失的 `curl` 命令。

## 插件添加了什么 [#what-the-plugin-adds]

插件是一个名为 `echolot` 的技能，附带它的参考文件。任务涉及项目的 API 时，Claude 会载入它。

| 部分 | 它为 Claude 提供什么 |
| --- | --- |
| 技能 | 何时使用 Echolot，怎样设置项目，每个请求的循环（环境、创建、发送、检查、报告），以及批准被拒绝时该怎么做 |
| 设置参考 | 安装 Echolot、连接 MCP 服务器、策略、工具集和机密 |
| 请求文件参考 | 工作区中每种请求的 TOML：HTTP、GraphQL、WebSocket、Socket.IO、MQTT、gRPC 和 MCP |
| 示例做法 | 冒烟测试套件、OpenAPI 文档、分页、实时检查、模拟服务器、流程、测试 MCP 服务器、CI |
| 一个脚本 | 创建一个带有 `local` 和 `production` 环境的空工作区 |

插件不含任何会自行运行的代码，也没有服务器：Claude 仍然通过 MCP 服务器和[命令行工具](/docs/cli)访问 Echolot，
批准和限制如[外部智能体](/docs/ai/agents)所述。

## 安装之前 [#before-you-install]

你需要：

- **Claude Code**，支持插件。
- **Echolot 的命令行工具**，位于你的 `PATH` 中，这样 `echolot --version` 才能运行。参见[命令行工具](/docs/cli)。

<Edition only="appstore">
  App Store 版的 App 内没有命令行工具。请单独安装命令行工具（**设置 › 智能体**中的**获取命令行工具**会带你前往下载）；
  插件搭配它使用，方式相同。
</Edition>

## 安装插件 [#install-the-plugin]

<Steps>
<Step>
在 Claude Code 中添加 Echolot 市场：

```text
/plugin marketplace add staticdreams/echolot-claude-plugin
```
</Step>
<Step>
从中安装插件：

```text
/plugin install echolot@echolot
```
</Step>
<Step>
按下文所述，让 Claude 设置你的项目。插件只需安装一次；每个项目只需设置一次。
</Step>
</Steps>

要获取较新的版本，请运行 `/plugin marketplace update echolot`。要移除插件，请运行
`/plugin uninstall echolot@echolot`。

## 设置项目 [#set-up-a-project]

在项目的文件夹中，对 Claude 说：

```text
为这个项目设置 Echolot
```

Claude 随后会做以下这些事，不做别的：

1. 检查 `echolot` 能否运行。
2. 在项目中查找工作区，也就是名称以 `.echolot` 结尾的文件夹。如果没有，它会在项目的根目录创建一个，
   带有 `local` 和 `production` 环境，并把项目用到的主机添加为变量。
3. 问你一个问题：你想在 Echolot App 中批准它的更改，还是让它无人值守地工作。
   参见[批准还是无人值守](#approvals-or-unattended)。
4. 为项目注册 Echolot 的 MCP 服务器。这会在项目的根目录写入 `.mcp.json`：

   ```sh
   claude mcp add --scope project echolot -- echolot mcp serve ./alpenglow.echolot --toolsets all --env local
   ```

5. 提议在项目的 `CLAUDE.md` 中添加一段简短的说明，写明对你的 API 的调用经由 Echolot 进行。

然后它会停下来，告诉你接下来要做什么：

1. 如果你选择了在 App 中批准，请在 Echolot 中打开工作区，在**设置 › 智能体**中开启**允许智能体使用打开的工作区**，
   并在**供智能体使用的工具**下开启你想要的工具集。在你开启其他工具集之前，App 提供**请求**和**流程**。
2. 重新启动 Claude Code，或者运行 `/mcp`，然后批准该项目的服务器。

请提交工作区和 `.mcp.json`。两者都不含机密，你的队友可以从仓库得到同样的设置。

## 批准还是无人值守 [#approvals-or-unattended]

MCP 服务器在启动时决定自己以哪种方式运行。

| 运行方式 | 会发生什么 |
| --- | --- |
| 工作区已在 Echolot 中打开，且智能体已开启 | Claude 的调用在 App 内运行。更改，或者可能更改数据的发送，会在表单中询问你。你会看到每个请求出现在边栏中。 |
| 独立运行，使用 `--policy permissive` | 发送和更改无需询问即可运行。删除会被拒绝，发送到受保护的环境和新主机也会被拒绝。 |
| 独立运行，未指定策略 | 读取和安全的发送可以运行。其他一切都会被拒绝。 |

在 App 中批准适合开发的时候：你看着 Claude 做了什么，也可以拒绝它。无人值守适合你不想全程守着的长任务。
要在两者之间切换，请在 Echolot 中打开或关闭工作区，然后运行 `/mcp` 重新连接。各项策略参见[独立运行](/docs/ai/agents#on-its-own)。

## 可以让它做什么 [#what-to-ask-for]

你不需要提到 Echolot。项目有了工作区之后，Claude 就会用它来调用该项目的 API。

| 你说 | Claude 在 Echolot 中做什么 |
| --- | --- |
| “以演示用户的身份登录，列出我的订单” | 把密码存储为机密，存储一个登录请求并让它保留响应中的令牌，再用该令牌发送列表请求。令牌永远不会到达对话。 |
| “为订单 API 做一个冒烟测试套件” | 一个文件夹，包含列出、获取、创建、更新，以及各自的一个失败用例，都带有检查，并通过它们保留的值串联起来。然后它运行该文件夹，报告哪些失败了。 |
| “这个页面需要一个愿望清单 API，但它还不存在” | 一个模拟服务器，根据你的 OpenAPI 文档创建，或者使用手工创建的路由和示例数据，外加针对其路由的请求。 |
| “为什么这个端点过一阵子就会失败？” | 反复发送该请求，比较历史记录中的交换记录，然后说明问题出在 API 还是测试。 |
| “检查订单事件是否到达 WebSocket” | 打开会话，用另一个请求下单，然后读取会话收到的内容。 |
| “测试我们 MCP 服务器的工具” | 添加该服务器并检查它，为每个工具存储一个调用，并对其结果加上检查。 |
| “登录，创建订单，然后轮询直到它送达” | 用这些块绘制一个流程。你批准之后它才会运行。 |
| “在 CI 中运行 API 测试” | 适用于你的流水线的 `echolot run` 命令，带有报告，并列出它需要的机密的名称。 |

每一行都会在工作区中留下东西：请求、检查、模拟服务器或流程，你可以在 Echolot 中打开、更改并再次运行。

## Claude 不做什么 [#what-claude-does-not-do]

技能让 Claude 遵守这些规则：

- **凭据不进入文件，也不进入对话。** 你给它的密码或密钥会立即存入机密变量，此后只会出现 `{{它的名称}}`。
  令牌由 Echolot 从登录的响应中保留，从不经过 Claude。
- **不删除**，除非你要求删除该项目。
- **不对受保护的环境或生产环境做测试**，除非你要求。发送到受保护的环境始终会询问你。
- **不擅自编写脚本。** 脚本是你必须信任的代码：Claude 提出脚本并说明它放在哪里，Echolot 会在它运行之前询问你。
- **不做超出你要求的事。** “设置一下”就只是设置。“测试这个端点”就是针对该端点的请求和检查，而不是一整个套件。
- **不悄悄换用别的工具。** 批准被拒绝或缺少工具时，Claude 会说明需要什么，然后等待。它不会退回去使用 `curl`。

## 疑难解答 [#troubleshooting]

- **Claude 仍然使用 `curl`。** 检查插件是否已安装（`/plugin`），项目是否有工作区，以及 `/mcp` 是否将 `echolot` 服务器列为已连接。
  如果是，请把说明添加到你的 `CLAUDE.md`：对 Claude 说“把 Echolot 的说明添加到 CLAUDE.md”。
- **更改被拒绝，也没有任何询问。** 服务器在独立运行。请在 Echolot 中打开工作区，开启**允许智能体使用打开的工作区**，
  然后运行 `/mcp` 重新连接。或者让 Claude 把服务器切换到 permissive 策略。
- **Claude 说缺少某个工具。** 它所在的工具集已关闭。请在**设置 › 智能体**的**供智能体使用的工具**下开启它，然后重新连接。
- **Claude 写的请求没有出现。** 独立运行的服务器在启动时读取工作区。请运行 `/mcp` 并重新连接 `echolot`。
  经由 App 时，新请求会立即出现。
