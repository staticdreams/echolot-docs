Echolot에는 계정도 클라우드도 없습니다. 요청은 Mac의 파일에 남고, 비밀 값은 키체인에 남으며, 사용자가 직접 보내거나 무언가를 켜지 않는 한 사용자나 작업
공간에 관한 어떤 것도 Mac을 떠나지 않습니다. 이 페이지는 Echolot이 하는 일을, 그리고 그것만을 나열합니다.

## 사용자의 파일 [#your-files]

- <strong>작업 공간</strong>은 저장한 위치에 있는 일반 TOML 파일의 폴더입니다. Echolot은 작업 공간을 절대 업로드하지 않습니다.
- <strong>Echolot 자체의 데이터</strong>(저장된 응답 본문, 기록, 충돌 보고서, 어시스턴트 대화)는 이 Mac의 `~/Library/Application Support/Echolot`에 있습니다.
  <strong>설정 › 정보 › 응답 및 기록 › Finder에서 보기</strong>로 엽니다. App Store 에디션은 이를 자체 컨테이너에 보관합니다. [에디션](/docs/get-started/editions)을
  참조하세요.
- 패널 레이아웃, 신뢰한 스크립트와 서버 같은 <strong>개인적인 선택</strong>은 작업 공간이 아니라 이 Mac의 앱 설정에 보관됩니다.

## 비밀 값은 키체인에 있습니다 [#secrets-stay-in-the-keychain]

비밀 값은 작업 공간 파일에 들어가지 않으므로 작업 공간을 Git에 커밋할 수 있습니다.

- <strong>비밀 변수</strong>는 로그인 키체인에만 저장됩니다. 파일에는 변수의 이름만 있고 값은 키체인에 있습니다. [비밀 값](/docs/workspaces/secrets)을 참조하세요.
- <strong>가져오기</strong>는 인증과 자격 증명 헤더에서 찾은 비밀번호, 토큰, 키를 비밀 변수로 옮기며, 가져오기 보고서에는 이름만 나오고 값은 절대 나오지 않습니다.
  [가져오기](/docs/get-started/importing)를 참조하세요.
- <strong>내보내기</strong>는 비밀 값을 절대 기록하지 않습니다. 비밀 변수는 이름만 나가며, 내보내기 보고서는 요청에 평문으로 입력된 자격 증명의 개수를 알려 줍니다.
- 토큰을 비밀 변수에 저장하는 <strong>응답 캡처</strong>는 키체인에만 기록합니다.
- 어시스턴트의 모델 키, MCP 로그인 토큰, 프록시 비밀번호도 키체인에 있습니다. 평문으로 입력한 프록시 비밀번호나 인증서 암호문에는 <strong>키체인으로 이동</strong>이
  있는 경고가 표시됩니다.
- 명령줄 도구는 같은 키체인 항목을 읽습니다. 다른 앱이나 다른 에디션이 항목을 읽으려 하면 macOS가 한 번 묻습니다. <strong>항상 허용</strong>을 선택하세요.

## 자격 증명은 해당 서버에만 전달됩니다 [#credentials-stay-with-their-server]

리디렉션이 다른 출처(다른 스킴, 호스트, 포트)로 이어지면 Echolot은 따라가기 전에 자격 증명을 제거합니다. `Authorization`, `Cookie`, 일반적인 API 키
헤더, API 키 인증의 헤더, 비밀 값이 들어 있는 모든 헤더, Digest, AWS, 클라이언트 인증서 설정이 해당됩니다. 한 서버를 위해 설정한 비밀 값은
리디렉션을 통해 다른 서버로 전달되지 않습니다.

## 디스크의 응답 본문 [#response-bodies-on-disk]

응답은 디스크로 스트리밍되며, 모든 전송은 이 Mac의 기록에 보관됩니다. <strong>설정 › 저장 공간</strong>이 얼마나 보관할지와 어떻게 저장할지를 정합니다.

| 설정 | 의미 |
| --- | --- |
| <strong>디스크에 저장된 응답 본문 암호화</strong> | 본문, 통신 캡처, 서식이 적용된 사본이 로그인 키체인에 보관된 키로 암호화되므로 그 키 없이는 Echolot의 저장 폴더에서 응답의 어떤 부분도 읽을 수 없습니다. 저장된 본문은 백그라운드에서 암호화되며, 끄면 복호화됩니다. |
| <strong>응답 본문 최대 보관 크기</strong> | 이 크기를 넘으면 가장 오래전에 사용한 본문부터 제거됩니다. 탭에 열려 있는 본문은 항상 유지됩니다. |
| <strong>요청당 기록</strong> | 각 요청이 보관하는 응답의 개수. |

암호화가 켜져 있는 동안 기록 검색은 본문 내용이 아니라 요청의 이름, 주소, 헤더로 요청을 찾습니다. 기록의 검색 색인은 암호화되지 않으므로 본문 텍스트를
보관하지 않으며, 암호화를 켜면 색인에 있던 본문 텍스트가 제거됩니다. 작업 공간은 영향을 받지 않습니다. [저장 공간과 암호화](/docs/workspaces/storage-and-encryption)를
참조하세요.

## 보호된 환경 [#protected-environments]

환경(예: Production)을 보호됨으로 표시하면 그 환경이 활성인 동안 시작하는 모든 전송이 먼저 묻습니다. 요청의 <strong>보내기</strong>(이때 <strong>Production에 보내기…</strong>로
표시됨), 연결, 실행 페이지의 실행, 수동 플로 실행, 빠른 보내기와 단축어 동작, MCP 호출과 검사, <strong>토큰 받기</strong>, 스키마 가져오기, gRPC 리플렉션입니다.
질문에는 환경의 이름과 나갈 내용이 표시되며 비밀 값은 가려집니다.

<strong>취소</strong>가 기본 버튼이므로 <kbd>Return</kbd>으로는 보호된 환경에 실수로 보낼 수 없고, <kbd>Esc</kbd>도 취소합니다. 
<strong>환경을 전환할 때까지 다시 묻지 않음</strong>은 환경이 바뀔 때까지 그 윈도우에서 묻는 것을 멈추며, 절대 저장되지 않습니다. 에이전트는 항상 묻습니다.
[보호된 환경](/docs/workspaces/protected-environments)을 참조하세요.

## 스크립트와 로컬 프로그램 [#scripts-and-local-programs]

- <strong>스크립트</strong>(요청 전 스크립트와 테스트 스크립트)는 Echolot 안의 샌드박스에서 실행됩니다. 스크립트는 Echolot을 통해서만, 사용자가 직접 보낼 때와 같은
  규칙으로 요청을 보낼 수 있습니다.
- 스크립트는 <strong>이 Mac에서</strong> 신뢰한 뒤에만 실행됩니다. Echolot에서 직접 작성한 스크립트는 신뢰됩니다. 다른 곳에서 들어온 스크립트(가져오기, `git pull`,
  Echolot 밖에서의 편집)는 <strong>스크립트 검토…</strong>를 선택해 신뢰할 때까지 전송을 막습니다. 신뢰는 스크립트의 내용을 기준으로 작업 공간 밖에 보관되므로 작업
  공간이 자신의 스크립트를 스스로 신뢰할 수는 없습니다.
- <strong>로컬 프로그램으로 실행되는 MCP 서버</strong>는 MCP 서버 페이지에서 그 명령을 승인(<strong>신뢰하고 확인</strong>)한 뒤에만 시작됩니다. 명령, 인수, 환경이 바뀌면 다시
  묻습니다.

## 어시스턴트와 모델 제공업체 [#the-assistant-and-model-providers]

어시스턴트와, 켜 둔 경우 Echo의 AI 코멘트는 <strong>설정 › 어시스턴트</strong>에서 선택한 모델 제공업체를 사용합니다.

- 모델 키는 이 Mac의 키체인에 남으며 제공업체 자체의 주소로만 전송됩니다.
- <strong>제공업체로 보내는 첫 번째 메시지는 무엇이든 보내기 전에 묻습니다.</strong> 제공업체마다 한 번이며(호환 서버는 호스트별) 질문에는 무엇이 전송되는지가 표시됩니다.
  어시스턴트의 경우 사용자의 메시지, 어시스턴트가 읽는 작업 공간 데이터, 도구 결과입니다. 비밀 값은 절대 전송되지 않습니다.
- Echo의 AI 코멘트는 일어난 일에 관한 짧은 사실(요청의 종류, 상태 코드, 소요 시간)만 전송하며 이름, 주소, 헤더, 본문, 변수, 비밀 값은 절대 보내지
  않습니다.
- Apple의 온디바이스 모델과 이 Mac의 서버(예: Ollama)는 묻지 않습니다. 어떤 것도 Mac을 떠나지 않기 때문입니다.
- <strong>설정 › 어시스턴트 › 데이터를 받을 수 있음</strong>에는 허용한 제공업체가 <strong>취소</strong>와 함께 나열됩니다. 취소한 제공업체는 다음에 다시 묻습니다.
- 어시스턴트는 데이터를 변경하거나 새 호스트에 접속하기 전에 묻고, 외부 에이전트와 같은 도구와 규칙으로 작동합니다.

[어시스턴트](/docs/ai/assistant)를 참조하세요.

## 외부 AI 에이전트 [#external-ai-agents]

Claude Code, Cursor, Codex 같은 에이전트는 사용자가 허용한 경우에만 Echolot의 MCP 서버를 통해 작업 공간을 사용할 수 있습니다.

- <strong>기본값은 꺼짐입니다.</strong> <strong>설정 › 에이전트 › 에이전트가 열린 작업 공간을 사용하도록 허용</strong>으로 켜며, 각 작업 공간은 <strong>작업 공간 설정 › 에이전트</strong>에서
  에이전트를 끌 수 있습니다.
- <strong>이 Mac에서만 가능합니다.</strong> 서버는 표준 입력과 출력, 또는 토큰이 있는 `127.0.0.1`에서 수신합니다. 네트워크에서는 아무것도 도달하지 못합니다.
- <strong>사용자가 승인합니다.</strong> 기본적으로 읽기와 안전한 전송은 실행되고, 데이터를 변경할 수 있는 전송, 새 호스트, 작업 공간 변경은 사용자에게 묻습니다
  (<strong>거부</strong>, <strong>한 번 허용</strong>, <strong>이 세션 동안 허용</strong>). 보호된 환경과 새 호스트는 항상 묻습니다.
- <strong>비밀 값은 에이전트에 절대 전달되지 않습니다.</strong> 에이전트는 비밀 값을 이름으로 참조합니다. 에이전트가 돌려받는 모든 것은 오류를 포함해 비밀 값이 그대로,
  JSON 형태로, 퍼센트 인코딩과 Base64로 제거된 상태입니다. 에이전트가 읽는 기록은 자격 증명이 가려져 있으며,
  아무도 저장하지 않은 `access_token`처럼 응답 본문의 자격 증명 필드도 마찬가지입니다.
- <strong>제공되지 않는 것이 있습니다.</strong> 에이전트 정책, 프록시, 인증서, 인증, 스크립트 저장은 에이전트가 사용할 수 있는 도구가 아닙니다.
  에이전트는 스크립트를 제안할 수 있습니다. 사용자는 그 이유와 변경 내용을 보며, **저장하고 신뢰**만 스크립트를 쓰고 신뢰합니다.
- <strong>모든 호출이 기록됩니다.</strong> 기록에는 각 요청을 누가 보냈는지가 에이전트 이름과 함께 표시되며, 윈도우의 <strong>에이전트</strong>에는 최근 호출이 나열됩니다.

[에이전트](/docs/ai/agents)와 [AI 에이전트가 작업 공간을 안전하게 사용하게 하기](/docs/tutorials/agents-safely)를 참조하세요.

## 사용 데이터와 충돌 보고서 [#usage-data-and-crash-reports]

둘 다 <strong>설정 › 개인정보 보호</strong>에 있습니다. 사용 데이터는 기본값이 꺼짐이고, 이 Mac에 보관되는 충돌 보고서는 켜짐입니다.

- <strong>익명 사용 데이터 공유.</strong> 켜면 Echolot이 어떤 기능이 사용되는지(요청 보내기, 실행, MCP 검사)를 요청 종류와 상태 코드 같은 작은 사실과 함께 개발자에게
  알리고, 오류를 스택 트레이스와 함께 보고합니다. URL, 헤더, 본문, 변수, 비밀 값, 응답은 절대 포함되지 않습니다. 데이터는 Echolot이 사용하는 분석 서비스인
  PostHog로 전송됩니다.
- <strong>충돌 보고서 수집.</strong> 기본값은 켜짐입니다. macOS가 다음 실행 때 Echolot에 충돌 및 멈춤 보고서를 전달하면 Echolot이 이를 이 Mac에 저장하므로 버그 신고에
  첨부할 수 있습니다. 보고서에는 스택 트레이스만 들어 있으며 어디로도 전송되지 않습니다. <strong>Finder에서 보기</strong>로 엽니다.

## Echolot이 스스로 하는 연결 [#connections-echolot-makes-on-its-own]

사용자가 보내는 요청 외에 Echolot은 다음의 경우에만 네트워크에 연결합니다.

| 항목 | 시점 | 전송하는 내용 |
| --- | --- | --- |
| <strong>업데이트 확인</strong>(직접 다운로드 버전) | <strong>자동으로 업데이트 확인</strong>이 켜져 있으면 하루에 한 번, 또는 <strong>업데이트 확인…</strong>을 선택할 때 | GitHub에 릴리스 목록을 요청합니다. GitHub는 앱의 버전과 IP 주소를 볼 수 있습니다. |
| <strong>베타 상태</strong>(직접 다운로드 버전, 베타 빌드) | 실행할 때와 하루에 한 번 | 쿠키나 저장된 자격 증명 없이 GitHub Pages에서 서명된 작은 파일을 가져옵니다. 이 파일로 베타 빌드를 일찍 끝내거나 연장할 수 있습니다. |
| 응답 트리의 <strong>이미지 미리보기</strong> | JSON이나 XML 트리에서 이미지 주소 위에 포인터를 올려 둘 때만 | 쿠키나 저장된 자격 증명 없이 브라우저처럼 그 이미지를 최대 10 MB까지 가져옵니다. 기록에는 남지 않으며 스크립트를 실행하지 않습니다. |
| <strong>사용 데이터</strong> | 켠 경우에만 | 위를 참조하세요. |
| <strong>사용자의 모델 제공업체</strong> | 어시스턴트나 Echo의 AI 코멘트를 사용하고 사용자가 허용한 뒤에만 | 위를 참조하세요. |

App Store 에디션은 업데이트나 베타 확인을 하지 않습니다. 업데이트는 App Store가 처리합니다.
