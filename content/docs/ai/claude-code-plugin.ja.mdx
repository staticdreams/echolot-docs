Echolotプラグインは、Claude CodeにEcholotの使い方を教えます。Echolotの[MCPサーバ](/docs/ai/agents)がエージェントにツールを提供し、
プラグインはそれをいつ、どう使うかをClaudeに伝えます。どのプロトコルにどのツールを使うか、ワークスペースをプロジェクトのどこに置くか、
認証情報を会話に出さないためにどうするか、といったことです。プラグインがあれば、開発中にClaudeが行うリクエストはワークスペースに保存され、
チェックされ、履歴に残り、あなたがアプリで開けるものになります。セッションが終わると消えてしまう `curl` コマンドにはなりません。

## プラグインが追加するもの [#what-the-plugin-adds]

プラグインは、`echolot` という名前の1つのスキルと、その参照ファイルでできています。タスクがプロジェクトのAPIに関わるとき、
Claudeがこのスキルを読み込みます。

| 部分 | Claudeに与えるもの |
| --- | --- |
| スキル | Echolotを使う場面、プロジェクトのセットアップ方法、すべてのリクエストで行う手順（環境、作成、送信、チェック、報告）、承認が拒否されたときの対応 |
| セットアップの参照ファイル | Echolotのインストール、MCPサーバの接続、ポリシー、ツールセット、シークレット |
| リクエストファイルの参照ファイル | あらゆる種類のリクエスト（HTTP、GraphQL、WebSocket、Socket.IO、MQTT、gRPC、MCP）に対応する、ワークスペースのTOML |
| レシピ | スモークテストのスイート、OpenAPIドキュメント、ページネーション、リアルタイムのチェック、モック、フロー、MCPサーバのテスト、CI |
| スクリプト | `local` と `production` の環境を持つ空のワークスペースを作成します |

プラグインには、単独で実行されるコードもサーバも含まれていません。Claudeは引き続き、MCPサーバと[コマンドラインツール](/docs/cli)を通じて
Echolotを使い、[外部エージェント](/docs/ai/agents)で説明している承認と制限が適用されます。

## インストールの前に [#before-you-install]

次のものが必要です。

- プラグインに対応した**Claude Code**。
- `PATH` 上にある**Echolotのコマンドラインツール**。`echolot --version` が動作する状態にします。
  [コマンドラインツール](/docs/cli)を参照してください。

<Edition only="appstore">
  App Store版には、アプリ内のコマンドラインツールがありません。コマンドラインツールを別途インストールしてください
  （**設定 › エージェント**の**コマンドラインツールを入手**からダウンロードできます）。プラグインは、それを使って同じように動作します。
</Edition>

## プラグインをインストールする [#install-the-plugin]

<Steps>
<Step>
Claude Codeで、Echolotのマーケットプレイスを追加します。

```text
/plugin marketplace add staticdreams/echolot-claude-plugin
```
</Step>
<Step>
そこからプラグインをインストールします。

```text
/plugin install echolot@echolot
```
</Step>
<Step>
以下のように、プロジェクトのセットアップをClaudeに頼みます。プラグインのインストールは1回だけ、セットアップはプロジェクトごとに1回だけ行います。
</Step>
</Steps>

新しいバージョンを入手するには、`/plugin marketplace update echolot` を実行します。プラグインを削除するには、
`/plugin uninstall echolot@echolot` を実行します。

## プロジェクトをセットアップする [#set-up-a-project]

プロジェクトのフォルダで、Claudeに次のように頼みます。

```text
このプロジェクトにEcholotをセットアップして
```

Claudeは次のことを行い、それ以外のことは行いません。

1. `echolot` が実行できることを確認します。
2. プロジェクト内のワークスペース、つまり名前が `.echolot` で終わるフォルダを探します。なければ、プロジェクトのルートに作成し、
   `local` と `production` の環境を用意して、プロジェクトが使うホストを変数として追加します。
3. あなたに1つだけ質問します。変更をEcholotアプリで承認するか、無人で作業させるかです。
   [承認か、無人実行か](#approvals-or-unattended)を参照してください。
4. EcholotのMCPサーバをプロジェクトに登録します。これにより、プロジェクトのルートに `.mcp.json` が書き込まれます。

   ```sh
   claude mcp add --scope project echolot -- echolot mcp serve ./alpenglow.echolot --toolsets all --env local
   ```

5. プロジェクトの `CLAUDE.md` に、APIの呼び出しはEcholotを通すという短い注記を追加することを提案します。

その後、Claudeは作業を止め、次に行うことを伝えます。

1. アプリでの承認を選んだ場合は、Echolotでワークスペースを開き、**設定 › エージェント**で
   **開いているワークスペースの使用をエージェントに許可**をオンにして、**エージェント用のツール**で使いたいツールセットをオンにします。
   ほかのツールセットをオンにするまで、アプリが提供するのは**リクエスト**と**フロー**です。
2. Claude Codeを再起動するか、`/mcp` を実行して、プロジェクトのサーバを承認します。

ワークスペースと `.mcp.json` をコミットしてください。どちらにもシークレットは含まれず、チームメイトはリポジトリから同じ設定を受け取れます。

## 承認か、無人実行か [#approvals-or-unattended]

MCPサーバは、起動時に動作のしかたを決めます。

| 動作のしかた | 起きること |
| --- | --- |
| ワークスペースがEcholotで開いていて、エージェントがオン | Claudeの呼び出しはアプリの中で実行されます。変更や、データを変更する可能性のある送信は、シートであなたに確認します。各リクエストがサイドバーに現れるのを確認できます。 |
| 単独で、`--policy permissive` を指定 | 送信と変更は確認なしで実行されます。削除は拒否され、保護された環境や新しいホストへの送信も拒否されます。 |
| 単独で、ポリシーの指定なし | 読み取りと安全な送信は実行されます。それ以外はすべて拒否されます。 |

アプリでの承認は、開発している最中に向いています。Claudeの操作を見守り、拒否することもできます。無人実行は、
付きっきりで見ていたくない長いタスクに向いています。一方からもう一方へ切り替えるには、Echolotでワークスペースを開くか閉じてから、
`/mcp` を実行して接続し直します。ポリシーについては[単独で動作する場合](/docs/ai/agents#on-its-own)を参照してください。

## 頼めること [#what-to-ask-for]

Echolotの名前を出す必要はありません。プロジェクトにワークスペースがあれば、Claudeはそのプロジェクトの
APIの呼び出しにワークスペースを使います。

| あなたの依頼 | ClaudeがEcholotで行うこと |
| --- | --- |
| 「デモユーザーでサインインして、自分の注文を一覧表示して」 | パスワードをシークレットとして保存し、レスポンスのトークンを保持するサインインのリクエストを保存して、そのトークンで一覧を送信します。トークンが会話に出ることはありません。 |
| 「注文APIのスモークテストのスイートを作って」 | 一覧、取得、作成、更新と、それぞれに失敗するケースを1つずつ入れたフォルダを作ります。チェック付きで、保持した値によってつながっています。その後フォルダを実行し、失敗したものを報告します。 |
| 「このページには、まだ存在しないウィッシュリストAPIが必要」 | OpenAPIドキュメントから、または手作業で作ったルートとダミーデータでモックサーバを作り、そのルートへのリクエストも作ります。 |
| 「このエンドポイントは、なぜしばらくすると失敗するの？」 | リクエストを繰り返し送信し、履歴のやり取りを比較して、APIとテストのどちらに原因があるかを伝えます。 |
| 「注文のイベントがWebSocketに届くことを確認して」 | セッションを開き、別のリクエストで注文を出して、セッションが受信した内容を読み取ります。 |
| 「うちのMCPサーバのツールをテストして」 | サーバを追加して調べ、ツールごとに、結果のチェックを付けた呼び出しを保存します。 |
| 「サインインして、注文を作成して、配達されるまでポーリングして」 | それらのブロックでフローを作図します。あなたが承認すると実行されます。 |
| 「APIのテストをCIで実行して」 | パイプライン用の `echolot run` コマンドを、レポートと、必要なシークレットの名前とともに用意します。 |

どの行も、ワークスペースに何かを残します。リクエスト、チェック、モック、フローなどで、Echolotで開き、変更し、
もう一度実行できます。

## Claudeが行わないこと [#what-claude-does-not-do]

スキルは、Claudeに次のルールを守らせます。

- **認証情報をファイルや会話に書かない。** あなたが渡したパスワードやキーは、すぐにシークレット変数に入り、それ以降は
  `{{その名前}}` だけが現れます。トークンはEcholotがサインインのレスポンスから保持し、Claudeを経由することはありません。
- **削除しない。** あなたがその項目の削除を頼んだ場合は別です。
- **保護された環境や本番環境に対してテストしない。** あなたが頼んだ場合は別です。保護された環境への送信は、
  常にあなたに確認します。
- **自分の判断でスクリプトを保存しない。** スクリプトは、あなたが信頼しなければならないコードです。Claudeはスクリプトを提案して保存先を伝え、
  Echolotは実行の前にあなたに確認します。
- **頼まれた以上のことをしない。** 「セットアップして」はセットアップだけです。「このエンドポイントをテストして」は
  そのエンドポイントのリクエストとチェックであり、スイートではありません。
- **黙ってツールを替えない。** 承認が拒否されたときや、ツールがないとき、Claudeは必要なものを伝えて待ちます。
  `curl` に切り替えることはありません。

## トラブルシューティング [#troubleshooting]

- **Claudeがまだ `curl` を使う。** プラグインがインストールされていること（`/plugin`）、プロジェクトにワークスペースがあること、
  `/mcp` で `echolot` サーバが接続済みと表示されることを確認してください。それでも使う場合は、`CLAUDE.md` に注記を追加します。
  Claudeに「CLAUDE.mdにEcholotの注記を追加して」と頼んでください。
- **変更が拒否され、何も確認されない。** サーバが単独で動作しています。Echolotでワークスペースを開き、
  **開いているワークスペースの使用をエージェントに許可**をオンにして、`/mcp` を実行して接続し直してください。
  または、サーバをpermissiveポリシーに切り替えるようClaudeに頼みます。
- **Claudeがツールがないと言う。** そのツールセットがオフになっています。**設定 › エージェント**の
  **エージェント用のツール**でオンにして、接続し直してください。
- **Claudeが書いたリクエストが表示されない。** 単独で動作しているサーバは、起動時にワークスペースを読み込みます。
  `/mcp` を実行して `echolot` を接続し直してください。アプリ経由の場合、新しいリクエストはすぐに表示されます。
