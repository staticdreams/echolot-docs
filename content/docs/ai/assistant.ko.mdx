어시스턴트는 Echolot에 내장된 AI 에이전트입니다. “Create order가 왜 실패해?”, “이 요청에 대한 검사를 작성해 줘”처럼 평소 쓰는 말로
물으면, 외부 에이전트가 받는 것과 같은 도구로 작업 공간에서 일합니다. 요청을 나열하고 읽고, 요청을 보내고, 응답을 읽고, 검사를
작성하고, 명세를 편집하고, 모의 서버를 시작하고, 플로를 실행합니다. 어시스턴트가 하는 모든 호출은 진행되는 대로 패널에 표시되며,
데이터를 변경할 수 있는 작업은 먼저 사용자에게 묻습니다.

## 어시스턴트 열기 [#open-the-assistant]

어시스턴트는 모든 페이지의 오른쪽에 고정되는 패널입니다. 다음 중 하나로 열거나 닫습니다.

- <kbd>⌘</kbd><kbd>J</kbd>
- <strong>보기 › 어시스턴트 보기</strong>(또는 <strong>어시스턴트 가리기</strong>)
- 페이지 헤더의 버튼 중 마지막인 요술봉 버튼

윈도우마다 자신의 어시스턴트가 있으며, 그 윈도우의 작업 공간에서 일합니다.

패널을 더 넓히려면 왼쪽 가장자리를 왼쪽으로 드래그합니다. 페이지의 최소 너비까지 페이지의 공간을 차지합니다. 오른쪽으로 드래그하면
좁아지고, 가장자리를 더블 클릭하면 기본 너비로 돌아갑니다.

## 모델 제공업체 선택 [#choose-a-model-provider]

패널을 처음 열면 <strong>모델 선택</strong>이라고 표시됩니다. <strong>어시스턴트 설정 열기…</strong>를 선택하거나 <strong>설정 › 어시스턴트</strong>를 열고
<strong>제공업체 추가</strong>에서 제공업체를 추가합니다.

| 제공업체 | 입력할 내용 | 비고 |
| --- | --- | --- |
| <strong>Anthropic</strong> | <strong>API 키</strong> | Claude 모델. 계정마다 <strong>노력 수준</strong> 설정이 있습니다. <strong>모델 기본값</strong>, `low`, `medium`, `high`, `xhigh`, `max` 중에서 고릅니다. |
| <strong>OpenAI</strong> | <strong>API 키</strong> | |
| <strong>Google Gemini</strong> | <strong>API 키</strong> | |
| <strong>OpenAI 호환</strong> | <strong>주소</strong>와 <strong>API 키(선택 사항)</strong> | OpenAI의 Chat Completions API를 따르는 모든 서버(Ollama, LM Studio, OpenRouter 등). 다른 주소를 입력하지 않으면 주소는 `http://127.0.0.1:11434/v1`(이 Mac의 Ollama)입니다. |
| <strong>CLI 에이전트(ACP)</strong> | <strong>에이전트</strong>와 <strong>명령어</strong> | Agent Client Protocol을 따르는, Mac에 있는 코딩 에이전트. 직접 다운로드 버전에서만 사용할 수 있습니다. 아래를 참조하십시오. |

<strong>추가</strong>를 선택합니다. Echolot이 제공업체의 모델을 불러와 첫 번째 모델을 고릅니다. 다른 모델은 계정의 <strong>모델</strong> 메뉴에서 선택하고,
목록을 다시 가져오려면 <strong>모델 불러오기</strong>를 선택합니다. 제공업체가 모델 목록을 제공하지 않으면 <strong>모델</strong> 필드에 모델 이름을 직접
입력합니다.

어시스턴트를 무료로, 오프라인으로 써 보려면 [Ollama](https://ollama.com)에서 모델을 실행하고 기본 주소로 <strong>OpenAI 호환</strong>
제공업체로 추가합니다.

### 키는 키체인에 보관됩니다 [#keys-stay-in-the-keychain]

API 키는 이 Mac의 로그인 키체인에 저장되며 작업 공간에는 절대 저장되지 않고, 제공업체 자신의 주소로만 전송됩니다. 계정 옆의
<strong>제거…</strong>를 선택하면 키체인에서 그 키가 삭제됩니다.

### 제공업체 전환 [#switch-between-providers]

제공업체가 여러 개이면 <strong>설정 › 어시스턴트 › 제공업체</strong>에서 체크 표시된 것을 어시스턴트가 사용합니다. 패널에서도 전환할 수 있습니다.
패널 헤더의 모델 메뉴에는 모든 계정이 *제공업체 · 모델* 형식으로 나열되며, 그 아래의 <strong>어시스턴트 설정…</strong>은 설정을 엽니다.

### 로컬 코딩 에이전트(CLI 에이전트) [#local-coding-agents-cli-agent]

<Edition only="direct">
  로컬 CLI 에이전트는 직접 다운로드 버전에서만 사용할 수 있습니다. App Store 버전은 Mac에 설치된 프로그램을 시작할 수 없습니다.
  App Store 버전에서는 API 키, Ollama 또는 다른 OpenAI 호환 서버를 사용하십시오.
</Edition>

CLI 에이전트는 자신의 모델과 로그인을 가지고 옵니다. Echolot은 작업 공간 폴더에서 에이전트를 시작하고 Echolot의 MCP 서버를 통해
작업 공간을 전달하므로, 먼저 <strong>설정 › 에이전트 › 에이전트가 열린 작업 공간을 사용하도록 허용</strong>을 켜십시오([외부 에이전트](/docs/ai/agents)
참조). 제공업체로 <strong>CLI 에이전트(ACP)</strong>를 선택한 다음 <strong>에이전트</strong>를 고릅니다.

| 에이전트 | 명령어 | 필요한 것 |
| --- | --- | --- |
| <strong>Claude Code</strong> | `npx -y @zed-industries/claude-code-acp` | Node.js. Claude 구독 또는 `ANTHROPIC_API_KEY`를 사용합니다 |
| <strong>Codex</strong> | `npx -y @zed-industries/codex-acp` | Node.js. ChatGPT 로그인 또는 `OPENAI_API_KEY`를 사용합니다 |
| <strong>Gemini CLI</strong> | `gemini --experimental-acp` | Gemini CLI 설치 |
| <strong>기타</strong> | 입력한 명령어 | 표준 입출력으로 ACP를 사용하는 모든 에이전트 |

나중에 계정의 <strong>명령어</strong> 필드에서 명령을 바꿀 수 있습니다. 대화마다 자신의 에이전트 프로세스가 생기며, 윈도우를 닫으면 종료됩니다.
에이전트 자체의 권한 요청도 사용자에게 묻습니다.

## 일회성 권한 [#the-one-time-permission]

제공업체에 첫 메시지를 보내기 전에 Echolot이 묻습니다. <strong>*제공업체*(으)로 보내시겠습니까?</strong> 이 질문에는 무엇이 전송되는지(사용자의
메시지, 어시스턴트가 읽는 작업 공간 데이터, 도구 결과), 어디로 가는지, 그리고 비밀 값은 절대 전송되지 않는다는 점이 적혀 있습니다.
<strong>취소</strong>가 기본 버튼이므로 <kbd>↩</kbd>로 실수로 전송되는 일은 없습니다. 계속하려면 <strong>허용</strong>을 선택합니다.

Echolot은 제공업체마다 한 번 묻습니다. Anthropic에 한 번, OpenAI에 한 번, Gemini에 한 번, OpenAI 호환 서버마다(호스트 기준으로) 한 번,
CLI 에이전트마다 한 번입니다. 이 Mac의 서버(`localhost`, `127.0.0.1`, `::1`)는 Mac 밖으로 나가는 것이 없으므로 묻지 않습니다.
네트워크의 다른 곳에 있는 서버는 묻습니다.

<strong>설정 › 어시스턴트 › 데이터를 받을 수 있음</strong>에는 허용한 모든 제공업체가 나열됩니다. <strong>취소</strong>를 누르면 권한을 철회하며, 다음
메시지에서 다시 묻습니다.

## 질문하기 [#ask]

패널 아래쪽의 <strong>어시스턴트에게 묻기…</strong>에 입력합니다. <kbd>↩</kbd>는 보내기, <kbd>⇧</kbd><kbd>↩</kbd>는 줄 바꿈, <kbd>⌘</kbd><kbd>.</kbd>는
어시스턴트가 작업하는 동안 중지입니다.

새로운 대화는 현재 보고 있는 페이지에 맞는 제안으로 시작합니다. 제안을 클릭하면 텍스트 필드에 입력됩니다.

| 페이지 | 제안 |
| --- | --- |
| 요청 | <strong>이 작업 공간의 모든 요청을 보내고 어떤 요청이 실패하는지 알려 줘.</strong> · <strong>열려 있는 요청이 왜 실패해? 마지막 응답을 봐 줘.</strong> · <strong>열려 있는 요청의 최근 응답으로 검사를 작성해 줘.</strong> · <strong>이 목록의 모든 페이지를 가져와서 항목을 CSV로 저장해 줘.</strong> |
| MCP 서버 | <strong>이 MCP 서버를 확인하고 제공하는 기능을 요약해 줘.</strong> · <strong>이 서버의 읽기 전용 도구를 각각 한 번씩 호출하고 결과를 알려 줘.</strong> |
| 명세 | <strong>린터가 이 명세에서 보고한 문제를 수정해 줘.</strong> · <strong>이 작업 공간의 요청을 OpenAPI 명세로 문서화해 줘.</strong> |
| 모의 서버 | <strong>이 명세의 모의 서버를 시작하고 새로운 환경이 그 서버를 가리키게 해 줘.</strong> · <strong>최근의 실제 응답을 명세에 예시로 저장해 줘.</strong> |
| 플로 | <strong>로그인한 다음 목록의 모든 페이지를 내보내는 플로를 만들어 줘.</strong> · <strong>이 플로의 마지막 실행이 왜 실패했어?</strong> |

### 열려 있는 항목이 함께 전달됩니다 [#what-you-have-open-goes-along]

텍스트 필드 위의 칩에는 지금 열려 있는 항목이 표시됩니다. 열려 있는 요청, 테스트 페이지와 실패한 검사, 실행의 마지막 실행 결과, 열려
있는 명세, 모의 서버, 플로, MCP 서버입니다. 각 칩은 메시지와 함께 전송되므로 “이 요청”이나 “마지막 실행”이라고 말할 수 있습니다. 칩을
클릭하면 다음 메시지에서 제외되고, 다시 클릭하면 되돌아옵니다. 칩 위에 포인터를 올리면 모델에게 전달되는 문장을 볼 수 있습니다.

### 어시스턴트가 할 수 있는 일 [#what-the-assistant-can-do]

어시스턴트는 [외부 에이전트](/docs/ai/agents#toolsets)에게 제공할 수 있는 모든 도구 그룹을 가지고 있으며, 설정 › 에이전트에서
무엇을 켜 두었는지와 관계없습니다. 요청과 응답, 검사와 함께 폴더 실행, 기록, 환경, 작업 공간의 폴더와 변수, 명세, 모의 서버, MCP
서버, 플로가 해당됩니다. 승인은 이 모든 도구에 여전히 적용됩니다.

에이전트 정책, 프록시, 인증서, 작업 공간 인증, 스크립트를 변경하는 도구는 절대 받지 못합니다.

대화에는 말만 남습니다. 어시스턴트가 하는 일은 텍스트 필드 바로 위의 트레이에 표시됩니다. 작업 중에는 실행 중인 호출이 한 줄로 표시되고,
끝나면 호출 수와 실패한 수가 표시됩니다. 트레이를 클릭하면 모든 호출의 목록이 열리고, 호출을 클릭하면 입력과 결과를 볼 수 있습니다.
텍스트 필드 아래의 줄에는
지금까지 사용한 토큰 수와, 모델의 가격이 알려져 있으면 대략의 비용이 표시됩니다.

## 변경 사항 승인 [#approve-what-changes]

어시스턴트가 정책상 묻게 되어 있는 작업을 하려고 하면 윈도우에 시트가 나타납니다. ***에이전트*에서 *데이터를 변경할 수 있는 요청을
보내려고 합니다***라는 문구와 함께 호출과, 비밀 값을 가린 상태로 실제 전송될 요청이 표시됩니다.

<Shot id="ai-assistant-approval" alt="승인 시트: 에이전트가 데이터를 변경할 수 있는 요청을 보내려고 하며, 전송될 POST 요청과 거부, 이 세션 동안 허용, 한 번 허용 버튼이 보입니다" />

- <strong>한 번 허용</strong>은 이 호출을 실행합니다.
- <strong>이 세션 동안 허용</strong>은 윈도우가 닫힐 때까지 이 호출과 비슷한 호출을 묻지 않고 실행합니다. 작업 공간에 대한 모든 변경이 한꺼번에
  해당되며, 어떤 도구가 수행하든 상관없습니다(요청 만들기, 폴더 인증 저장, 환경 변경 등). 전송은 같은 호스트에 대한 같은 메서드가
  해당됩니다(`demo.echolot.dev`로의 모든 GET). 삭제는 계속 묻고, 보호된 환경, 새로운 호스트, 플로의 버전처럼 일반 변경보다 범위가 좁은
  경우도 계속 묻습니다. 이런 경우에는 같은 호출에만 적용됩니다. 시트에는 무엇이 해당되는지 적혀 있습니다.
- <strong>변경 및 전송 전에 묻지 않기</strong>는 변경과 데이터를 변경하는 전송에 대해 시트에 나타나는 체크 상자입니다. 체크한 상태로 허용하면
  아래에 설명하는 <strong>설정 › 어시스턴트 › 사전 확인</strong>이 켜집니다. 삭제, 새로운 호스트, 보호된 환경에는 나타나지 않습니다.
- <strong>거부</strong>는 호출을 거절하며, 어시스턴트에게 그 사실이 전달됩니다.

새로운 호스트로의 전송, 보호된 환경으로의 전송, 삭제에서는 <strong>한 번 허용</strong>이 기본 버튼이 아니므로 <kbd>↩</kbd>로 승인할 수 없습니다.
5분 안에 답하지 않은 질문은 거부됩니다. 여러 호출이 대기 중이면 시트에 남은 호출 수가 표시됩니다.

무엇을 묻는지는 작업 공간의 에이전트 규칙에 따라 달라집니다. 규칙이 없으면 다음과 같습니다.

| 어시스턴트의 동작 | 작업 공간 규칙이 없을 때 |
| --- | --- |
| 요청 및 환경 읽기 | 실행 |
| 안전한 전송(GET, GraphQL 쿼리, MCP 읽기) | 실행 |
| 기타 전송(POST, PUT, PATCH, DELETE, 파일 본문) | 묻기 |
| 보호된 환경으로 전송 | 항상 묻기 |
| 새로운 호스트로 전송(작업 공간의 어떤 요청이나 환경도 사용하지 않는 호스트) | 항상 묻기 |
| 작업 공간 변경 | 묻기 |
| 삭제(항목은 휴지통으로 이동) | 묻기 |

### 더 적게 묻기 [#ask-less]

<strong>설정 › 어시스턴트 › 사전 확인 › 삭제, 새로운 호스트 및 보호된 환경에 대해서만 묻기</strong>를 켜면 전송과 변경에 대한 질문이 사라집니다.
어시스턴트가 요청, 환경, 명세, 모의 서버, 플로를 만들고 POST, PUT, DELETE 요청을 묻지 않고 보냅니다. 모든 호출은 여전히 대화에
표시됩니다. 항목을 휴지통으로 이동하는 경우, 어시스턴트가 시작될 때 작업 공간이 사용하지 않던 호스트, 보호된 환경은 계속 묻고,
에이전트에게 제공되지 않은 플로를 실행하는 경우도 마찬가지입니다. 이 설정은 켜기 전까지 꺼져 있으며 어시스턴트에만 적용됩니다.
외부 에이전트는 작업 공간의 규칙을 따릅니다.

이 규칙을 느슨하게 하거나 엄격하게 하려면, 또는 호스트와 전송을 제한하려면 <strong>작업 공간 설정 › 에이전트</strong>를 사용하십시오.
[에이전트용 작업 공간 규칙](/docs/ai/agents#workspace-rules)을 참조하십시오. 같은 규칙이 외부 에이전트에도 적용됩니다. 거기서
<strong>에이전트의 이 작업 공간 사용 허용</strong>이 꺼져 있으면 어시스턴트도 그 작업 공간에서 일하지 않습니다.

### 보호된 환경 [#protected-environments]

[보호된 환경](/docs/workspaces/protected-environments)이 활성화되어 있는 동안에는 메서드나 규칙과 관계없이 어시스턴트가 보내는 모든
전송이 먼저 묻습니다. <strong>이 세션 동안 허용</strong>을 선택해도 같은 호출에만 적용됩니다.

## 모델이 절대 보지 못하는 것 [#what-the-model-never-sees]

- <strong>비밀 값.</strong> Echolot은 모델로 무엇이든 전송되기 전에 메시지, 도구 결과, 오류에서 모든 비밀 변수의 값을 치환합니다. 모델은 비밀
  변수를 이름으로만 봅니다.
- <strong>사용자의 패턴.</strong> <strong>설정 › 어시스턴트 › 모델에게 숨김</strong>은 한 줄에 정규식 하나를 받습니다. 도구가 반환하는 내용에서 일치하는
  모든 부분은 모델이 보기 전에 `[hidden]`으로 치환됩니다. 고객 ID나 이메일 주소처럼 비밀 변수가 아닌 데이터에 쓰십시오. 올바른
  정규식이 아닌 줄은 빨간색으로 표시되고 적용되지 않습니다.
- <strong>응답 본문 전체.</strong> 응답은 핸들과 함께 요약(상태, 헤더, 소요 시간, 개요와 본문의 첫 바이트, 검사 결과)으로 모델에 전달됩니다.
  본문의 더 많은 부분은 그 핸들을 통해 JSONPath나 검색 단위로 한 번에 조금씩 읽습니다.

다음 메시지와 함께 정확히 무엇이 전송되는지 보려면 패널 헤더의 눈 모양 버튼, <strong>모델이 보는 내용</strong>을 선택합니다. 지침, 도구, 대화,
컨텍스트가 토큰 추정치와 함께 표시됩니다.

## 대화 보관 [#keep-a-conversation]

대화는 이 Mac에 작업 공간별로 보관됩니다. 패널 헤더에서 다음을 사용합니다.

- <strong>새로운 대화</strong>(연필)는 새 대화를 시작합니다.
- <strong>이전 대화</strong>(시계)는 <strong>이 Mac에서</strong> 보관된 대화와 <strong>이 작업 공간에 공유됨</strong>의 대화를 나열합니다. 클릭하면 엽니다.
- 보관 메뉴(화살표가 있는 트레이)는 대화를 오래 남는 것으로 바꿉니다.

| 명령 | 동작 |
| --- | --- |
| <strong>테스트로 저장</strong> | *어시스턴트 · 대화 제목* 폴더를 만들고, 어시스턴트가 보낸 전송마다 요청 하나를 순서대로 번호를 붙여 담습니다. 각 요청에는 받은 상태에 대한 검사가 들어 있습니다. |
| <strong>플로로 저장</strong> | 같은 폴더에 더해, 그 요청들을 차례로 보내는 플로를 만듭니다. |
| <strong>작업 공간에 공유</strong> | 비밀 값을 치환한 대화를 Markdown 대화록과 기록으로 작업 공간의 `assistant/` 폴더에 저장합니다. 팀원이 Git pull 후 읽고 <strong>이 작업 공간에 공유됨</strong>에서 열 수 있습니다. |
| <strong>호출 재실행</strong> | 모델 없이 대화의 도구 호출을 순서대로 다시 실행하고, 결과를 새로운 대화로 보여 줍니다. 승인은 다른 호출과 마찬가지로 적용됩니다. |

<strong>테스트로 저장</strong>과 <strong>플로로 저장</strong>은 대화에서 요청을 한 번 이상 보낸 뒤에 사용할 수 있습니다.

## 이 Mac의 Apple Intelligence [#apple-intelligence-on-this-mac]

Apple Intelligence가 켜져 있는 macOS 26에서 Echolot은 작은 작업에 Apple의 온디바이스 모델도 사용합니다. 이 작업은 Mac 밖으로
나가지 않으며 제공업체나 권한이 필요하지 않습니다.

- 응답 패널의 Apple Intelligence 메뉴: <strong>응답 요약</strong>, <strong>오류 설명</strong>(오류 응답에 대해), <strong>검사 제안</strong>(Echolot이 실행할 수 있는 검사를
  추가하는 버튼 포함), <strong>이름 제안</strong>(요청 이름을 바꾸는 버튼 포함).
- 실패한 플로 실행의 <strong>실패 원인 설명</strong>과 실행 중인 모의 서버 로그의 <strong>로그 요약</strong>.
- 켜 두었을 때의 [Echo의 코멘트](/docs/ai/echo#ai-comments).

각 답변에는 <strong>이 Mac에서 응답했습니다. 어디에도 전송되지 않았습니다.</strong>라고 표시됩니다. 모델을 사용할 수 없으면 이 버튼들은 나타나지
않습니다. 어시스턴트 패널 자체는 항상 설정 › 어시스턴트의 제공업체를 사용합니다.

## 모델로 서버의 도구 시도하기 [#try-a-servers-tools-with-a-model]

[MCP 서버](/docs/mcp-servers/tools-and-quality) 페이지의 <strong>모델로 시도</strong> 카드는 모델이 서버의 도구 중 무엇을 고를지 보여 줍니다.
<strong>이 서버로 에이전트에게 어떤 작업을 요청하겠습니까?</strong>에 누군가 에이전트에게 요청할 만한 내용을 입력하고 <strong>시도</strong>를 선택합니다.
설정 › 어시스턴트에서 선택한 모델이 서버의 도구를 보고, 어떤 도구를 어떤 인수로 호출할지 알려 줍니다. 실제로 호출되는 것은
없습니다. 도구의 입력 스키마에 맞지 않는 호출은 무엇이 잘못되었는지 보여 주며, 이렇게 해서 불분명한 도구 이름과 설명이 드러납니다.

제공업체로 처음 시도하면 어시스턴트와 같은 일회성 권한을 묻습니다. CLI 에이전트는 여기서 사용되지 않습니다.

## 문제 해결 [#troubleshooting]

- <strong>“설정 › 어시스턴트에서 먼저 모델 제공업체를 선택하십시오.”</strong> 체크된 제공업체가 없습니다. 제공업체를 추가하거나 **설정 ›
  어시스턴트 › 제공업체**에서 하나를 체크하십시오.
- <strong>“이 작업 공간에서는 에이전트가 꺼져 있습니다”</strong>: <strong>작업 공간 설정 › 에이전트 › 에이전트의 이 작업 공간 사용 허용</strong>이 꺼져 있습니다
  (`workspace.toml`의 `[agents] enabled = false`). 어시스턴트를 쓰려면 켜십시오.
- <strong>제공업체가 추가 또는 모델 불러오기 후에 오류를 표시합니다.</strong> 키를 확인하고, OpenAI 호환 서버라면 그 주소에서 실행 중인지
  확인하십시오. 메시지에 제공업체와 무엇이 잘못되었는지 나와 있습니다.
- <strong>CLI 에이전트가 시작되지 않습니다.</strong> 터미널에서 그 명령이 실행되는지, **설정 › 에이전트 › 에이전트가 열린 작업 공간을
  사용하도록 허용**이 켜져 있는지 확인하십시오.
